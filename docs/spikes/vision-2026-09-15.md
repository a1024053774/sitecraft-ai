# T1 DeepSeek 视觉 spike 纪要

- 运行日期：2026-09-15
- 模型 / base URL：脚本默认模型为 `deepseek-v4-flash`；本次使用项目环境映射后的 `deepseek-v4-flash-vision-exp`，`https://api.deepseek.com`（不含 key）
- 脚本：`scripts/spike-vision.mjs`（`npm run spike:vision`）
- 范围：只验证 Chat Completions 的 `content[]` + `image_url` data URL。没有 fallback、重试、视觉文案 schema、`commitOperations`。

## 命令

环境变量未注入时（任务要求的裸命令）：

```bash
node scripts/spike-vision.mjs
```

退出码 **1**。未发出 HTTP 请求，错误为「未配置 DEEPSEEK_API_KEY，拒绝伪造视觉结果」。

有本地 `.env.local` 时，由 Node 加载环境（脚本本身不读该文件），再跑同一脚本：

```bash
node --env-file=.env.local scripts/spike-vision.mjs
```

退出码 **0**。这是一次历史实测；本次使用 `env.md` 临时映射的复测也以退出码 0 成功，详情见下表。

未提供远程 URL 时拒绝伪造：

```bash
node scripts/spike-vision.mjs --mode remote-url
```

退出码 **1**，错误为「需要 --url … 拒绝伪造远程测试」。

`--image <path>`、`--mode remote-url --url <https://…>`、`--max-bytes`（默认 10 MiB，本地硬上限）已实现，本次没有再打额外上游请求。

## 请求 JSON 结构示例

实际发出的是 OpenAI-compatible `POST /chat/completions`，`messages[0].content` 为数组。base64 用 `<redacted>` 代替，未使用 Chat/Anthropic 的 `image` 私有字段。

```json
{
  "model": "deepseek-v4-flash",
  "temperature": 0,
  "max_tokens": 256,
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "Look at this image. Reply with JSON only: {\"ok\":true,\"note\":\"<one short English phrase>\"}"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "data:image/png;base64,<redacted>"
          }
        }
      ]
    }
  ]
}
```

## 已确认结论

1. **消息格式可用。** `messages[0].content` 数组里放一段 `text` 和 `{type:"image_url", image_url:{url:"data:image/png;base64,..."}}`，对内置 1×1 PNG 得到 HTTP 200、`finish_reason=stop`、非空 `choices`。
2. **图片编码格式。** 本地 PNG 按 magic bytes 定为 `image/png`，再编成 data URL；本次 payload（`image_url.url` 字节数）114，原图 68 bytes。
3. **模型名。** 此前用 `deepseek-v4-flash` 请求时上游响应为 `deepseek-flash`；本次用环境中的 `deepseek-v4-flash-vision-exp` 请求时响应仍为 `deepseek-flash`。T7 应记录响应里的 `model`，不要假定请求名与响应名相同。
4. **单图耗时 / token（仅此一张极小 PNG）。** 两次真实请求分别为 981ms / 284 tokens 和 1267ms / 279 tokens；不能外推到产品实拍图。
5. **缺 key 不得装绿。** 进程环境没有 `DEEPSEEK_API_KEY` 时明确报错并退出 1，不写假成功。
6. **远程模式缺 URL 不得装测。** `--mode remote-url` 且没有 `--url` 时退出 1，不编造远程请求。

## 对 T7 的直接影响

1. T7 analyze 走现有 `DEEPSEEK_*` + `POST {baseURL}/chat/completions`，超时可继续用约 45s；**不要**改用 Anthropic `/messages` 的 `image` block。
2. 本地上传文件先做 magic bytes → MIME，再发 `data:<mime>;base64,…`。扩展名不可信。
3. 在发请求前用本地上限拦住过大文件（建议继续 10 MiB），错误文案写「本地上限」，不要对用户说这是 DeepSeek 上限。
4. Prompt 里要求「只返回 JSON」时，这张小 PNG 的回复可被 `JSON.parse`；T7 仍应对模型输出做 zod 校验，不要把本次 38 字符、可解析当成文案 schema 已成立。
5. 计费与延迟按实拍图重测；本纪要里的 981ms/284 tokens 和 1267ms/279 tokens 只对 1×1 PNG 成立。
6. 依赖本纪要的前提：进程环境里要有真实 `DEEPSEEK_API_KEY`。裸 `node scripts/spike-vision.mjs` 在无 key 时会失败，这是预期。
