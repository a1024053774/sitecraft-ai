状态：`approved-for-execution`；版本 v1.0；更新 2026-10-13。
依据：[已记录需求](./intent.md)、[主线](./mainline.md)、[T-127 新路线决定](../../.project-map/tickets/T-127-route-model-writes-site.md)、grilling Round 14（Q20–Q25）、Round 17（Q26=B）、Round 18（Q27=A）；数据删除政策按 2026-09-18 用户决定。

## 1. 产品范围

近期做内部技术 Demo，由项目负责人扮演用户，用模拟资料测试任何行业的中小企业与机构展示型官网（T-156）。许可和数据归属按未来自助平台考虑，但不以真实客户试点或公开部署作为近期完成条件。

主路径：资料输入 → 风格/主题选择 → 可选需求对齐 → AI 建站 → 对话修改 → 浏览器预览验证 → 用户确认。

完整“一句话建站”目标保留；本次把其前置体验（风格选择、需求对齐）提前验证。按已批准的计划分模块执行，不等待全部旧任务完成才验证成品质量。

页面规划优先级已确认（Q18）：

1. 用户明确要求的页面、界面和单页/多页结构优先。
2. 用户未列页面时，模型按实际资料能撑起的内容规划页面，并在生成前显示计划。
3. 不使用固定默认页；资料少就少做，可以只有首页，用户补充后再丰富。

页面数量不固定。需支持用户要求和模型规划的不同页面集合及跨页导航；当前能力不匹配时明确说明和规划所需实现，不得默默缩成单页或固定三页，也不编造已经接通的后台业务。

## 2. 面向用户的风格选择

新建站点走 T-127 的站点代码路线。用户选择「帮我选」「精密工程」「现场实拍」「品牌画册」及「邻里日常」，并设置「版式：规整 ↔ 大胆」「信息：疏朗 ↔ 紧凑」两个滑杆（1–10，以 1–3 / 4–7 / 8–10 三档给出具体对齐、栏宽、尺度与留白指令，不增删资料内容）。未提交选择按站点和当前问题保存在浏览器；提交后的偏好与结构化选项保存在同一会话和站点记录中，刷新恢复。已生成站可在对话区选择「调整风格与疏密」，重新选择、规划、确认后仍经同一提交入口存新版本；待答问题只存简短要求，规划与写页从有效资料链取全文。选择「帮我选」时模型依据资料选风格并给理由；选定风格时模型不能替用户改选。历史问题中的下线选项不再显示；原偏好已下线时明确提示重新选择，不能把它静默替换为其他风格。

风格目录统一登记选项、短 skill 和真实缩略图来源；四种已验证风格均使用真实生成站首屏，邻里日常来自 T-159 的禾巷小馆版本 7be34b12；真实区分度以匿名对比包的独立盲评为准。pending 候选不出现在普通进程的风格卡或「帮我选」的模型合同中。服务端 SITECRAFT_EVAL_STYLES 可逗号列出已登记 pending 编号，经原 chat 选择门禁评估；未知或非 pending 编号在 Next 配置加载时使启动失败，旧评估会话在普通进程回看也不展示或授权该选项。模型任务领取与提交中的实际事实模型调用共用当前进程准入判定；初次规划检查本次偏好，后续模型任务检查当前大纲，未准入时明确拒绝、不创建任务、不静默改风格。恢复/撤销可沿用事实核对、手改可复用整组核对段时，照常执行确定性检查并存版；资料变化、核对依据未知或内容变化导致需要模型时，才在实际事实调用前复核准入；confirm 早拒还保留确认卡，重新选择已准入风格可以重新规划。用户确认页面大纲之后才写站点代码；初次大纲与正文只生成中文，英文由用户满意后单独生成。

页面骨架版式卡在 `skills/site-code-core/SKELETONS.md`，每次规划与写页随核心规范加载。规划时随机打乱卡片并记录实际顺序，模型返回顶层 `skeletonId`、`skeletonReason`；编号必须是现有卡片或 `custom`，拼错时以简短中文拒绝。理由说明主选的资料依据、首屏与后续节奏，并点名次合适那张及不选原因；不按行业或公司分配。分类目录入口仅适用于至少三个差别明显的产品或服务系列、且资料以分类目录为主。每页 `outline` 返回最多六个短句，服务端以分号连接为大纲文字，最大长度仍低于原 800 字上限。选择整理为 `skeleton: {id, reason}`，与 `skeletonOrder` 一同保存、刷新并传给写页；历史大纲没有记录时不补造。版式卡不是事实来源，所有站点仍经唯一提交入口检查存版。评估轮次的 `private/case-N/code-site.json` 保留大纲，可据其选择统计分布。

## 3. 工作台与会话

POST /api/sites 只接收站点名称，直接创建代码记录及会话，不创建旧草稿。列表、工作台、版本恢复与图片的存在性检查以代码记录为准。无有效站点参数时显示选择入口，只有显式新建操作创建记录；读取不存在的站点不隐式补默认站。工作台随查询参数变化重新加载，清除上一入口的状态和错误；创建完成后用站点编号替换新建标志，刷新继续打开同一站点。

当前需求对齐是持久化风格卡（帮我选、精密工程、现场实拍、品牌画册、邻里日常与两个滑杆）及页面大纲确认。问题 ID、修订号、选项、答案、epoch 与确认占用保存在同一会话；过期问题拒绝，重复确认不重复生成。开始任务后返回 202，等待问题返回 200。状态查询不自动重跑模型。规划、写页、修复与事实校对由站点代码 workflow 管理，无白名单修改或 SSE 分支。confirm_ops 仅是既有代码会话的确认卡标识，已无 operation schema 或执行器。

工作台保留资料导入、带许可信息的图片上传、三档预览、对话、版本历史、恢复和用户确认删除。中文预览可点选区块、写意见或使用快捷按钮；会话和批注线程 CRUD 保留。旧批注锚点只作为不透明记录保留，显示「旧批注，无法定位」，不再接受 slot/region 新建请求。

T-162 的中文预览提供「批注」模式：C 进入/切换，Esc 取消输入或退出模式，输入控件、可编辑元素及 IME 不截获 C。悬停高亮、点击后在目标附近写意见，375 用底部面板并留在预览；显示实际「修改范围：页面 · 区块」及具体元素提示。Enter 换行，⌘/Ctrl+Enter 添加，空意见不添加；Esc 将焦点还给预览。正常浏览保留链接导航、选择文字和滚动。

T-163 在批注模式支持拖框：移动超过 6 个屏幕 CSS 像素才算圈选，反向拖动归一成同一矩形，极小移动仍是点选。Esc、pointercancel、窗口失焦、滚动或预览缩放取消未完成框；不提供缩放手柄。框内可见内容按最近的可编辑区块归组，不把嵌套区块的外层边框误算成额外范围。只覆盖一个区块时沿用 selectedTarget，携带 elements 中各元素的区块内路径、标签和快照；多个区块先列出范围，用户选择一个后才写意见。坐标只用于工作台显示，不存入目标或发给模型。服务端逐项核对元素路径、标签和快照，任一失效在写作调用前拒绝；原单区块写回和范围检查不变。

意见框保持打开时，继续点选另一块后显式把焦点交给该目标的 textarea，不依赖首次挂载的 autoFocus。点选记录的 localStorage 读、写、删除都捕获存储拒绝，显示可见说明并保留当前内存操作；不把存储不可用扩大成工作台崩溃，也不承诺刷新恢复。草稿存储不可用时仍不能假装已保存。

历史版本回看期间四个快捷按钮停用，sendEdit 同时拦住手写或快捷修改，不发当前页/当前版本的编辑请求。界面提示「回到当前版本并重新点选后再修改」；返回当前版清空历史目标，再由用户明确点选。只读回看不能退回整页修改。

「添加批注」仅把编号草稿写入本站点 localStorage；每条含原始版本、修订号、目标、意见与发送状态，同版本刷新恢复。允许连续添加多条待发送草稿，添加后保持批注模式并释放当前选择，可直接悬停、点选或圈选下一处；对话框上方按列表顺序编号，可回看、编辑、逐条显式移除及发送；编辑保留原位置，移除后列表与预览编号同步重排，同一区块多条编号分开显示。版本变化保留旧意见，显示「来自 vX，请重新点选」，确认新目标后才允许发送。损坏的草稿原记录保留，不以空记录覆盖。

单条发送沿用 chat 的 selectedTarget 与 saveAnnotation，额外的 annotationSubmissionId 绑定一次发送快照并保存在 CodeRun。双击、刷新及相同标识重交不重复执行；刷新可能早于服务端认领，草稿继续冻结并查询原任务，用户可显式核对发送状态。未知状态不自动重发模型。发送期间仍可点选或圈选并新增草稿；冻结条目不能编辑、移除或重复发送。成功只归档这条草稿，失败保留意见与可见拒因，不自动重试；完成、拒收或 HTTP 丢失回复的处理均按 ID 更新当前集合，保留任务期间新增的意见。批注线程沿用服务端存储，定位切到原版本/页面，滚入 DOM 路径并展开意见；旧版本只读，不猜当前位置。修改结果不自动把 open 变成 resolved，用户可明确标为已处理或重新打开。旧 slot/region 锚点仍无法定位。

T-164 可从当前版本冻结多条草稿为一次批次。相同页面、版本和 DOM 路径的意见按添加顺序合成一组；祖先与后代路径重叠时先请求用户确认使用祖先范围，确认后合为一组，不在两个范围间交替写回。每组分别发送选中区块 HTML、相关 CSS、当前页大纲、资料原文和风格要点；候选均从同一父版本捕获并一次性组装，不能把意见拼成整站请求。提交入口接收目标并集，逐组核对 DOM、其他页面、共享 CSS、交互伪类和范围外匹配；任一组解析、冲突或底线失败，整批不存版本，各批注按 draftId 保留结果与拒因。批次沿用最多两轮局部修正和新区块事实核对规则；同一 annotationSubmissionId 的刷新、重交与任务认领只执行一次，发送期间新增草稿不进入冻结集合。

T-175 的「同项待补充提示」在提交入口为成功的中文局部或整页修改登记一次：仅采用本次新增「你的第 N 条消息」来源中已经通过事实核对的出处原句，扫描其他页面及本页修改范围外可批注的 main 正文，不扩大当前修改范围。每个 DOM 文本节点独立扫描，「待补充」前紧邻的事项名向左遇 Unicode 标点、换行或元素边界即止，去除首尾空白；空事项名和不足两个 Unicode 字符的事项名不匹配。出处按消息序号回读既有来源快照中的实际消息，只用 NFKC 与空白等价定位已通过引文对应的原始片段，不扩展到消息中的未采用句子。事项名必须完整逐字出现在该原始片段中，不规范化、不猜近义词、不调用匹配模型。单区块、多区块并集及整页范围内均排除；无新消息出处、上传、恢复、英文翻译及整站修改不新增提示。命中位置、页面名、原文片段、采用的原句及版本锚点保存在新版本的 stalePlaceholders 中，同一位置不因多条出处重复登记；读取或刷新不重新扫描、不追加提示。中文工作台对话仅呈现当前版本的一条提示，历史回看不显示。「一起更新」把这些位置按版本和提示序号加入既有批注草稿，先清理标题再选有效标签，空标题采用区块其他可用描述；锚点和完整草稿通过既有 schema 才加入，无法加入的位置在提示中说明，不写入非法草稿。保留已有及发送中草稿，不调用模型、不发送、不新建版本；重复点击和刷新不重复添加。同版本草稿可回看编辑，再由用户沿单条或多条批注入口确认发送；历史回看期间不能添加到当前版本。

375 回看定位时，预览按底部意见面板的实际高度留出空间，并滚动工作台预览区域，使目标标题、正文和链接在面板上方可见。线程面板可「收起」为一行意见摘要，目标高亮和原意见保留；「展开意见」恢复同一线程，Esc 回看时也收起，写意见时仍取消输入并归还焦点。1440/768 仍在目标旁显示，优先在目标下方或上方的可用空间内定位，并同时避开预览工具区、历史回看栏和返回当前版本按钮；上下都放不下时仅滚动工作台预览，为目标下方腾出空间，不把面板压到工具栏或目标上。用户主动滚动预览后停止自动腾位，目标位置更新不得再次改写阅读位置；再次点选目标、定位线程或重新展开浮层时恢复自动腾位。浮层完整留在视口内；目标滚出视野后，意见和操作控件仍完整可见，可继续输入及添加。`tests/t175-thread-placement.test.ts` 在三档以真实中心命中及点击核对历史返回，并对照浮层边界、目标避让与意见输入。面板定位和收起不改生成站代码、不保存新版本。

T-162 浏览器测试在测试进程内自建随机端口替身；发送/撤销通过临时 HTTP 服务调用生产 chat/history POST、执行原任务与唯一提交入口，仅控制 after 调度和模型响应。普通同目录 dev server 只提供界面、预览和持久化读回，未配置模型的 health 503 仍提供开发身份，须核对 cwd 和 dataRoot。标准 npm test 命令只需运行者设置 CHROME_PATH；入口每轮创建临时 SITECRAFT_DATA_ROOT、自启随机端口 dev server，把同一数据根与 SITECRAFT_BASE 传给测试进程，并在测试模块载入前核对身份，不一致即拒绝（T-167）。服务不配置真实模型，NODE_ENV=test 不加载 .env.local；日志与数据根路径留在 artifacts/t167/test-run-*/，临时数据保留供核查。入口从自身脚本位置确定工作树，cwd 不一致时在清理前拒绝；artifacts/t167/.run-tests.lock 按行记录 `{pid, startedAt}`，每份声明以一次 O_APPEND 写入；首个存活声明获得锁，从清理、登记到本轮结束持有。process.kill(pid, 0) 成功则明确拒绝并报告 pid 与锁路径，仅 ESRCH 或无法解析的记录允许接管，其他探测错误仍拒绝；并发接管不先删除再建，不等待或重试，只允许一个存活持有者。登记后核对打开的文件与锁路径仍指同一文件，避免上一轮正常释放期间持有已删除文件的描述符。普通退出释放锁，SIGKILL、OOM 或重启遗留的锁在下次启动接管并输出。新一轮开始前按时间保留最近五轮（含即将开始的一轮，不分成败），窗口外仅删除成功目录；失败、缺失或损坏报告的旧目录继续保留并输出路径，目录总数可超过五个。T-130 的隐私、API 和 CLI 夹具写入本轮数据根的 t130/，不再逐轮留在 artifacts/t130/（T-176）。入口静态沿项目内运行时 import/export、字面量 import()/require()、@/ 别名及 child_process 启动的本地 CLI／脚本（追踪参数变量、数组与 helper 链）递归识别 CHROME_PATH 等 Chrome 入口，忽略纯类型引用、注释和普通字符串，按引用能力保守分类并逐轮打印浏览器池文件与依赖依据，不维护文件名单。非浏览器池使用 Node 默认并发，之后浏览器池固定文件并发为 2，以同一候选两轮完整全量通过验收，获批实测的 --browser-concurrency=1（或 2、3）仅覆盖浏览器池上限。非浏览器池按进程祖先采样 Chrome 并记录所属测试文件，仅告警，不改分池、统计或通过条件；每文件每轮只执行一次，不先并行再补跑；两池共用本轮锁、服务和数据根，按原生每文件 summary 合并实际执行数及失败数，任一池失败或合计零用例均令整轮失败，定向文件沿用同一分类规则。全量须自然完成再判断，失败后不进入下一项，不中途终止。入口测试不代替实际 Next 集成证据。真实单条批注已另用实际 Next dev/after、DeepSeek 和独立预算账本完成，范围核对及用量见 T-162；预算上限由每次授权显式设置，不作为产品默认额度。

回调队列按 HTTP 请求隔离，任务终态与首次预览等待直接引用生产动态检查三档总预算加实测固定余量，任务等该请求实际 after 完成事件及 DOM 终态，动画只作既有点击与截图稳定检查，不用固定 sleep 或轮询次数判定超时。首条发送的冻结/刷新检查由替身响应闸门固定窗口，验证后才放行。三档只读场景复用合法版本，各场景仍有独立 Chrome 配置；需要修改版本的发送用例保持独立站点。性能验证记录分段耗时及负载，并发全量检查；发送/历史用例原 180s/120s 上限保持。

## 4. 站点代码、Skill 和提交契约

## 6. 质量、数据与执行边界

T-196 的视觉底线保留作者 aria 属性，先扫描访客默认状态，再展开原本关闭的 details 扫描并合并拒因；此外保留 T-192 要求的展开后去 aria 揭示态完整性扫描，三种状态合并去重；质量反馈结束后恢复原 open 和 aria 属性，不污染默认态底线文档。T-195 的文字自身最终 visibility 与完整有盒 sr-only 两条排除规则保持不变；微小或零盒中的文字按实际 Range 检查水平越界，仍保留 1px 容差与独立 scrollWidth 检查。CSS 生成文字由同次 Chrome DOMSnapshot 的实际文字行参与重叠、溢出与对比度，读取伪元素自身样式，不能用宿主 visibility 代替。失败位置沿用 T-173 的 pageId、width、documentElement 下元素 path 与 pseudo；当前版面修正无法核实伪元素声明的完整影响范围时明确拒收，不开放宿主或整页改写。

视觉扫描把 Chrome 实际绘制的非空 ::before／::after／::marker 文字归为生成文字；::marker 的 content:normal 仍按 display:list-item 与 listStyleType 识别原生编号，已有快照文字不因 computed content 为 normal 删除。first-letter／first-line 对真实 DOM 文字的包装仍交给原 DOM 文字路径；生成内容内部的首字母分片对 ::before／::after 均按真实生成目标核对，无法归属或证明已按自身样式测量时对该位置明确拒收。生成文字实际受祖先 first-line 规则影响而快照不能证明分片样式时同样拒收。构思主控于 2026-10-20 决定收口：::before、::after、::marker 及 ::first-letter／::first-line 中的文字，仅在宿主与该伪元素的 z-index 都为 auto、宿主与祖先均无带背景的 ::first-line／::first-letter、且 marker 为 outside 或宿主自身无背景时，才进入对比度测量。任一条件不满足，统一以「伪元素叠层无法核对实际底图」判为无法测量并拒收；不为同色、透明度或 z-index 添加豁免，不以背景盒覆盖文字推断文字未被遮挡。满足这些条件仍须通过既有快照完整性、分片样式、其他 before／after 绘制层及实际背景检查；这是一组必要条件。每次均将应保留的非空生成内容与快照位置核对，缺条目或实际文字行即报告无法测量并拒收；空快照列表不是覆盖证明，content-visibility 不新增排除。仅在通过上述门禁后，生成文字背景按实际文字行核实：背景实色与全部已知叠底相同时，覆盖与否不改变底色；其他情况完整覆盖才叠加，完全不相交不使用该背景层（html／body 可能向画布铺底，不能据此忽略）；部分覆盖、特殊形状或伪元素自身背景盒无法核实时明确拒收，不把宿主背景直接当作实际叠底。宿主与祖先的其他 ::before／::after 即使 content 为空也要核对是否绘制背景、边框、阴影或滤镜；存在其他绘制层而无法证明它位于生成文字下方且不影响实际叠底时，一律以「伪元素叠层无法核对实际底图」明确拒收；同实色仍可能从文字上方遮挡前景，不作豁免，也不凭矩形覆盖推断绘制顺序。独立叠层无法核实同样拒收。构思主控于 2026-10-20 决定将生成文字的保守叠层核对扩至兄弟及其他非祖先节点的 ::before／::after：同次 Chrome 快照保留无字伪元素的实际绘制盒，与被测文字相交且存在背景、边框、阴影等绘制时，一律以「伪元素叠层无法核对实际底图」无法测量拒收，不分析顺序、颜色或透明度；透明且无边框、阴影等绘制的伪元素不算。独立阴影可能伸出盒外，不能以盒不相交证明无影响，仍保守拒收。无法测量的原因随生成文字拒因保存；不开放额外修正范围。

### 浏览器存储与访客模型接口（T-202）

**访客模型接口**
- 设置页「模型接口」填写 API 地址、key、模型名，只存在 localStorage，可从浏览器清除。
- 只有可能调用模型的请求带 `X-SiteCraft-Provider-Base`、`X-SiteCraft-Provider-Key`、`X-SiteCraft-Provider-Model` 三个头：chat 的非 state 请求、撤销、恢复、看图；状态轮询不带。
- 路由把凭据放入本次请求的 AsyncLocalStorage；后台任务在调度时取出，放在闭包里，任务结束随之释放。凭据不进 run、modelCalls、日志或站点包。
- 生产模式（`NODE_ENV=production`）不读 `DEEPSEEK_API_KEY` 等环境变量。
- chat 中会启动模型任务的请求（翻译、风格选择、确认、已有版本后的修改），未配置时在对齐、来源登记和任务改动之前返回 400。
- 请求头不完整、地址不是 https、地址带账号、查询参数或锚点，均返回 400。
- 访客地址的连接限制：
  - 自定义 DNS lookup，任一解析结果落在回环、私网、链路本地、CGNAT、组播、保留地址或 IPv6 ULA 即拒绝；socket 连的就是校验过的地址。
  - 返回 3xx 报错，不跟随。
  - 仅当 `SITECRAFT_ALLOW_LOCAL_PROVIDER=1` 时放行 `http://127.0.0.1` 和 `http://localhost`，只用于本机验收。

**存储模式**
- `SITE_STORE=browser` 必须显式设置 `SITECRAFT_DATA_ROOT`，且该目录不能名为 `.sitecraft-data`；进程首次使用时清空其中的 code-sites、conversations、annotations、uploads。
- 对话与批注在该模式下用文件存储，即使 `NODE_ENV=production` 也不走 Postgres。

**工作区令牌**
- 首次调用 `/api/sites`（列表或创建）或 hydrate 时，服务器下发 `sitecraft_ws`（UUID v4）：HttpOnly、SameSite=Strict，https 下加 Secure。
- 内存登记表记录「站点 → 令牌、最后活跃时间」。`/api/sites/[siteId]/**` 全部经 `withSiteWorkspace`：令牌不符或站点未登记返回 404，放行时刷新活跃时间。
- 提交检查的 Chrome 用 `Network.setExtraHTTPHeaders` 带进程内随机密钥头，代替 cookie。
- `/api/sites` 列表只返回本令牌名下的站点，新建的站点登记到本令牌。

**站点存档**
- 格式：`{format:'sitecraft-site-bundle', version:1, siteId, updatedAt, files:[{path, data(base64)}]}`。只允许以下路径：`code-sites/<id>.json`、`annotations/<id>.json`、`conversations/<id>/<会话>.json`、`uploads/<workspace>/<id>/<文件>`。
- `POST /api/workspace/hydrate` 的检查：路径、解码后总大小（默认 20MB，超出返回 413）、站点记录的 siteId 与 route、各 JSON 能否解析。
  - 站点由别的令牌持有：返回 409。
  - 服务器副本的 `updatedAt` 不早于存档：保留服务器副本并返回它（`kept`）。
  - 该站点有任务在跑：返回 409。
  - 否则先腾出空间，再按存档逐文件写入。
- `GET /api/sites/[siteId]/bundle` 返回存档。ETag 由文件数、总大小和最新修改时间组成，同值返回 304。工作台每 5 秒拉一次，卸载时再拉一次。

**清理与容量**
- `sweep` 每分钟运行：闲置超过 `SITECRAFT_SESSION_IDLE_MS`（默认 30 分钟）且没有排队或运行中任务的副本被删除。
- 总量超过 `SITECRAFT_SESSION_CAP_BYTES`（默认 128MB）时，按闲置时长从久到短删除；只剩忙碌副本时 hydrate 返回 503。
- 服务器重启后，存档里仍是 running 的任务，由状态查询按既有规则标为中断。

**队列**
- 只在浏览器存储下生效：生成与检查并发为 1，等待上限 `SITECRAFT_QUEUE_WAITING`（默认 3），每个令牌同时只占一个位置。
- chat 在对齐、来源和任务改动之前预留位置；没被任务用上的预留在请求结束时释放。手改、撤销、恢复的提交同样排队。
- 排满返回 503「服务器忙」。排队中的任务把步骤显示为「服务器正在处理其他任务，已排队，轮到后自动开始」。

**发布与列表**
- 浏览器存储下 `/published/*` 返回 404，提示下载站点包。
- 首页、全部站点、手动删除读本地列表，不显示发布页和悬停预览。删除时同时删除服务器副本（已不在也算成功）和本地副本。
