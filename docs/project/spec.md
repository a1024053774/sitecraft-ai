# SiteCraft AI 产品与系统规格

状态：`approved-for-execution`；版本 v1.0；更新 2026-10-13。
依据：[已记录需求](./intent.md)、[主线](./mainline.md)、[T-127 新路线决定](../../.project-map/tickets/T-127-route-model-writes-site.md)、grilling Round 14（Q20–Q25）、Round 17（Q26=B）、Round 18（Q27=A）；数据删除政策按 2026-09-18 用户决定。
确认人：项目负责人。此状态批准按模块实施，不代表产品能力已实现或允许公开部署。

## 1. 产品范围

近期做内部技术 Demo，由项目负责人扮演用户，用模拟资料测试任何行业的中小企业与机构展示型官网（T-156）。许可和数据归属按未来自助平台考虑，但不以真实客户试点或公开部署作为近期完成条件。

主路径：资料输入 → 风格/主题选择 → 可选需求对齐 → AI 建站 → 对话修改 → 浏览器预览验证 → 用户确认。

完整“一句话建站”目标保留；本次把其前置体验（风格选择、需求对齐）提前验证。按已批准的计划分模块执行，不等待全部旧任务完成才验证成品质量。

页面规划优先级已确认（Q18）：

1. 用户明确要求的页面、界面和单页/多页结构优先。
2. 用户未列页面时，模型按实际资料能撑起的内容规划页面，并在生成前显示计划。
3. 不使用固定默认页；资料少就少做，可以只有首页，用户补充后再丰富。

页面数量不固定。需支持用户要求和模型规划的不同页面集合及跨页导航；当前能力不匹配时明确说明和规划所需实现，不得默默缩成单页或固定三页，也不编造已经接通的后台业务。

## 2. 面向用户的风格选择

新建站点走 T-127 的站点代码路线。用户选择「帮我选」「精密工程」「现场实拍」及「品牌画册」，并设置「版式：规整 ↔ 大胆」「信息：疏朗 ↔ 紧凑」两个滑杆（1–10，以 1–3 / 4–7 / 8–10 三档给出具体对齐、栏宽、尺度与留白指令，不增删资料内容）。未提交选择按站点和当前问题保存在浏览器；提交后的偏好与结构化选项保存在同一会话和站点记录中，刷新恢复。已生成站可在对话区选择「调整风格与疏密」，重新选择、规划、确认后仍经同一提交入口存新版本；待答问题只存简短要求，规划与写页从有效资料链取全文。选择「帮我选」时模型依据资料选风格并给理由；选定风格时模型不能替用户改选。历史问题中的下线选项不再显示；原偏好已下线时明确提示重新选择，不能把它静默替换为其他风格。

风格目录统一登记选项、短 skill 和真实缩略图来源；现有两种用真实评估站首屏，品牌画册按本轮真实生成补充首屏；真实区分度以匿名对比包的独立盲评为准。用户确认页面大纲之后才写站点代码；初次大纲与正文只生成中文，英文由用户满意后单独生成。

页面骨架版式卡在 `skills/site-code-core/SKELETONS.md`，每次规划与写页随核心规范加载。规划时随机打乱卡片并记录实际顺序，模型返回顶层 `skeletonId`、`skeletonReason`；编号必须是现有卡片或 `custom`，拼错时以简短中文拒绝。理由说明主选的资料依据、首屏与后续节奏，并点名次合适那张及不选原因；不按行业或公司分配。分类目录入口仅适用于至少三个差别明显的产品或服务系列、且资料以分类目录为主。每页 `outline` 返回最多六个短句，服务端以分号连接为大纲文字，最大长度仍低于原 800 字上限。选择整理为 `skeleton: {id, reason}`，与 `skeletonOrder` 一同保存、刷新并传给写页；历史大纲没有记录时不补造。版式卡不是事实来源，所有站点仍经唯一提交入口检查存版。评估轮次的 `private/case-N/code-site.json` 保留大纲，可据其选择统计分布。

## 3. 工作台与会话

POST /api/sites 只接收站点名称，直接创建代码记录及会话，不创建旧草稿。列表、工作台、版本恢复、图片与询盘的存在性检查以代码记录为准。无有效站点参数时显示选择入口，只有显式新建操作创建记录；读取不存在的站点不隐式补默认站。工作台随查询参数变化重新加载，清除上一入口的状态和错误；创建完成后用站点编号替换新建标志，刷新继续打开同一站点。

当前需求对齐是持久化风格卡（帮我选、精密工程、现场实拍与两个滑杆）及页面大纲确认。问题 ID、修订号、选项、答案、epoch 与确认占用保存在同一会话；过期问题拒绝，重复确认不重复生成。开始任务后返回 202，等待问题返回 200。状态查询不自动重跑模型。规划、写页、修复与事实校对由站点代码 workflow 管理，无白名单修改或 SSE 分支。confirm_ops 仅是既有代码会话的确认卡标识，已无 operation schema 或执行器。

工作台保留资料导入、带许可信息的图片上传、三档预览、对话、版本历史、恢复和用户确认删除。中文预览可点选区块、写意见或使用快捷按钮；会话、线索和批注线程 CRUD 保留。旧批注锚点只作为不透明记录保留，显示「旧批注，无法定位」，不再接受 slot/region 新建请求。

T-162 的中文预览提供「批注」模式：C 进入/切换，Esc 取消输入或退出模式，输入控件、可编辑元素及 IME 不截获 C。悬停高亮、点击后在目标附近写意见，375 用底部面板并留在预览；显示实际「修改范围：页面 · 区块」及具体元素提示。Enter 换行，⌘/Ctrl+Enter 添加，空意见不添加；Esc 将焦点还给预览。正常浏览保留链接导航、选择文字和滚动。

意见框保持打开时，继续点选另一块后显式把焦点交给该目标的 textarea，不依赖首次挂载的 autoFocus。点选记录的 localStorage 读、写、删除都捕获存储拒绝，显示可见说明并保留当前内存操作；不把存储不可用扩大成工作台崩溃，也不承诺刷新恢复。草稿存储不可用时仍不能假装已保存。

历史版本回看期间四个快捷按钮停用，sendEdit 同时拦住手写或快捷修改，不发当前页/当前版本的编辑请求。界面提示「回到当前版本并重新点选后再修改」；返回当前版清空历史目标，再由用户明确点选。只读回看不能退回整页修改。

「添加批注」仅把编号草稿写入本站点 localStorage；每条含原始版本、修订号、目标、意见与发送状态，同版本刷新恢复。当前只允许一条待发送草稿，对话框上方可回看、编辑、显式移除及发送。版本变化保留旧意见，显示「来自 vX，请重新点选」，确认新目标后才允许发送。损坏的草稿原记录保留，不以空记录覆盖。

单条发送沿用 chat 的 selectedTarget 与 saveAnnotation，额外的 annotationSubmissionId 绑定一次发送快照并保存在 CodeRun。双击、刷新及相同标识重交不重复执行；刷新可能早于服务端认领，草稿继续冻结并查询原任务，用户可显式核对发送状态。未知状态不自动重发模型。成功归档这条草稿，失败保留意见与可见拒因，不自动重试。批注线程沿用服务端存储，定位切到原版本/页面，滚入 DOM 路径并展开意见；旧版本只读，不猜当前位置。修改结果不自动把 open 变成 resolved，用户可明确标为已处理或重新打开。旧 slot/region 锚点仍无法定位。

375 回看定位时，预览按底部意见面板的实际高度留出空间，并滚动工作台预览区域，使目标标题、正文和链接在面板上方可见。线程面板可「收起」为一行意见摘要，目标高亮和原意见保留；「展开意见」恢复同一线程，Esc 回看时也收起，写意见时仍取消输入并归还焦点。1440/768 仍在目标旁显示，目标下方放不下时移到上方，再统一将最终位置限制在视口内；目标滚出视野后，意见和操作控件仍完整可见，可继续输入及添加。面板定位和收起不改生成站代码、不保存新版本。

T-162 浏览器测试在测试进程内自建随机端口替身；发送/撤销通过临时 HTTP 服务调用生产 chat/history POST、执行原任务与唯一提交入口，仅控制 after 调度和模型响应。普通同目录 dev server 只提供界面、预览和持久化读回，未配置模型的 health 503 仍提供开发身份，须核对 cwd。标准命令只设 SITECRAFT_BASE/CHROME_PATH，不要求运行者或普通 dev server 配置模型；实际 Next 服务的模型发送及 after 调度集成由主控另行安排，入口测试不代替该边界证据。

## 4. 站点代码、Skill 和提交契约

- 模型直接输出 `header`、`footer`、`css` 和 `pages`，每页包含 ID、标题、HTML 片段。版式与文案由模型按资料和风格决定，不受区块/operation 白名单限制。公共页头页脚与一份 CSS 在各页共享。
- T-162 可在 selectedTarget 附带 element（区块内元素子路径、标签及文字或图片 alt 快照）；服务端先在原区块内核对，再作为 pointedElement 传入局部写作。它只表达用户指向，不改 T-152 单区块边界。
- T-152 局部修改沿用 chat 请求，附带 `selectedTarget` 锚点（版本、页面、main 内元素路径、文字快照与标签）。前端本地保存同版本点选，换版本清除，服务端在认领任务及提交时核对版本；路径与快照不匹配则拒绝，不用相似文字或重复 id 猜位置。预览悬停与点选外框由工作台绘制，不写入生成站；系统部件不能单独点选。未进入点选时链接保留浏览器原生导航、页内锚点和语言切换，载入后同步工作台的当前页与语言。
- 局部修改不发送整站或版本目录；只给模型选中区块 HTML、匹配区块及其祖先的相关 CSS、当前页大纲、资料原文和所选风格的要点。局部核心合同为 `skills/site-code-core/LOCAL-EDIT.md`，不发送整站规划说明；有效资料仅去掉完全重复的副本并保留其最后出现顺序，不摘要、改写或截断原文。模型返回一个区块与新增 CSS，代码按原 DOM 位置写回；CSS 追加以区块专属类名开头的规则，不重写共享规则。提交入口在清理前后比较范围外 DOM、其他页和公共片段，比较修改前后原有与新增 CSS 规则对范围外元素的匹配及声明顺序，包含区块 DOM 改动触发的兄弟或 :has 规则变化；三档渲染中再匹配新增选择器，拒绝区块外命中、兄弟逃逸及跨区块计数器。选择器列表仅按顶层逗号拆分，保留函数、属性引号内的逗号。相关 CSS 提取、新选择器检查及外部规则匹配都按完整名称处理交互伪类，包括 focus-visible 和 focus-within，不能先匹配 focus 而留下后缀；外部焦点样式同样属于范围约束。HTML 与 CSS 生成文字的事实核对只包含新区块；全站布局与资源底线仍检查。越界、格式合同或底线拒收共用最多两轮局部修正，不改走整站写作，仍不过则不存版并提供「改整页」选择；HTTP、JSON 解析和截断错误不重试。
- 四个快捷按钮（更大胆、更克制、精简文字、换个版式）只是预设修改意见；选中时走局部修改，未选中时经原整站写作路线修改当前页，`pageId` 随每次候选（含修正）传入同一提交入口，拒绝其他页 HTML、公共片段或影响其他页的 CSS 变化。四种提示均明确保留事实、操作顺序和功能入口；精简只删重复与空话，保留衔接、必要解释和限制条件，用自然商务中文，不压成电报体。客户端发送锁和服务端任务认领防止连点重复调用。局部版本摘要包含页面和区块名；中文更新沿用英文落后提示。可选保存批注意见及任务结果，旧线程锚点和回复不删除，旧版本锚点明确要求重新点选。
- 局部写作回复先保存到任务的 `localResponses`，再解析和检查，后续事实校对报错也保留未存版的候选。局部事实校对固定非思考模式，输出额度为 4096 token，只收窄被校对的文字并对照资料原文；整站生成的事实校对继续使用既有思考配置和额度；恢复仅在无法沿用已有事实结论时调用，模式和额度不变；真实调用的阶段用量仍由任务记录报告。
- T-151：工作台在当前中文版检查通过后询问是否满意，用户主动点「生成英文版」。已有英文时标明基于中文第几版，按钮变为「按当前中文版重新翻译」；中文更新后提示英文版落后，不自动重译。翻译通过既有 chat 的 translate action 与后台任务，站点锁只认领一次；并发或过期请求返回 409，刷新不重复模型调用。
- 翻译固定非思考模式，公共页头页脚一批、每页一批，模型只见批内 s1…sN 短编号与文字，不见原 DOM 编号、HTML/CSS。与规划共用严格函数输出入口，走 beta 接口、strict=true，并强制调用 submit_english_translation；函数 ID enum 只列本批合法短编号。只接收唯一匹配的 tool_calls 函数参数，严格 JSON.parse 与 Zod 对象格式校验，不接受普通正文替代，不剥 Markdown 包装或修补坏 JSON；格式、截断与 HTTP 错误不重试。代码保存短编号到原 DOM 位置的映射，逐项核对编号覆盖；合法且唯一的译文保留，未知编号不写入 DOM，重复编号视为尚未收到唯一译文。只把缺失段落再次送去补译，沿用原短编号并收窄 enum，不整页重译；两轮总修正额度用完仍缺就失败。只有多余未知编号而没有缺失段落时明确失败，不编造补译目标。完整覆盖后才将译文写回文字节点、可见属性（alt/title/aria-label/aria-description/placeholder/data-label）与页面标题，写回时由代码确定转换全角标点为半角，跳过记录公司名及资料明确英文名的原样子串；受保护名称按最长匹配，不从正文猜名称，不靠模型改写、不做整段 NFKC。CSS、节点树、非文案属性、图片编号与系统部件原样保留；「待补充」固定为 To be provided，系统表单、署名标签与图标许可使用系统英文文本。自定义图片署名保留原许可文字，不让翻译改写作者或授权。
- 批准运行可设 SITE_CODE_TRANSLATION_TOKEN_LIMIT 正整数上限。发送每批前，以任务内已报告的翻译 usage，加下一批输入的保守估算与完整输出上限核对；预计超限、调用记录缺失或已用量未知时停止，不发送下一请求。另可用 SITE_CODE_TRANSLATION_OUTPUT_LIMIT 指定本次输出上限（1–16000），取它与原按文字量计算上限的较小值；输入、片段与检查不缩减，实际请求和调用记录保存相同 max_tokens。估算不是计费 tokenizer，实际用量以上游 usage 为准；截断仍失败，不为额度增加重试。

- T-154 的整站事实核对使用「核对段」：从 375/768/1440 渲染读取 HTML、alt/title/aria-label/data-label 和计算后的 CSS 文字，按整组内容与段文字共同去重，不能合并不同组的同文段；页面标题、所属标题和父级条件参与段文字比较。简单表格按行附表头和说明，合并单元格与表头作用域也参与比较；子 header、aside、列表和定义列表中的说明归入所在区块条件；跨行跨列表格、列表、定义列表及图片说明保留完整语义组。页面大纲每页发送一次，相邻标题只作上下文，不作为事实来源或额外待核内容。完整公司名是否仍出现作为独立观察，删除最后一处公司名也须重核。
- 模型对每个输入短编号返回一次问题数组，无问题也须显式返回空数组。未知、遗漏、重复编号或无效结构明确失败，不自动重试，不保存部分核对结论。首次生成核对全部段；后续比较完整有效资料、原始资料文本、段文字及其所在容器的完整有序内容；表格、列表、dl 或带标题小节内任一段新增、删除、改动或重排，整组都重新核对。组内仍有待核或被拒段时也整组发送，只有同一次核对中完整通过且未变化的组可以沿用，不能拼接多轮的部分通过。模型收到同组的短 groupId，用于共同核对条件与数值，完整组快照由代码保管。有效资料沿用现有局部输入的原文去重规则，保留补充的最后出现顺序，不用模型摘要；新对话要求改变有效资料文本时仍全核。复用仅来自当前已存版本和同一运行中已检查的候选；其他任务、来源不明、未核对导入和英文检查不能提供依据。版本与运行检查的 `factSegments.format=2` 保存资料、完整组内容、逐段结果、新核及沿用数量，直接比较原文，不做哈希；旧格式缺少分组依据，不用于核对段复用。片段与渲染都按 body 上下文解析，元素按顺序对应实际 DOM，片段文本从已清理的原文读取，不累计会合并或被丢弃的空白文本节点。`tests/t154-fact-segments.test.ts` 经提交入口拦截删条件行、删列表项、增行、重排行、部分通过拼接及片段空白／交界错位。被拒段继续核对，全部确定性检查每次重跑；局部修改的非思考核对、英文保真及恢复的既有规则保持。
- 事实来源包括原始资料和有效版本链中用户明确提供的补充；字段更新采用最新声明，设计要求不作为企业事实。模型生成的文案不进入资料链。撤销同时恢复该版本对应的用户补充链，后续修改不重新采用已撤销的信息。
- 新路线记录在 `.sitecraft-data/code-sites/<siteId>.json`，当前验收开发机文件存储。版本快照包含作者、一句话摘要、触发请求、完整代码、检查结果及时间；除可编辑的名称外均不可变。撤销与指定版本恢复携带客户端所见 `baseRevision`，同一提交入口拒绝过期版本并返回 409；通过后重新检查目标版本并存为新版本，保留所有旧版本，刷新读取当前版本。用户在既有删除流程输入站点编号确认后，一并删除代码版本、资料与运行记录；删除与提交共用站点锁。当前没有重做或自动删除。
- 恢复沿用事实结论的判断由提交入口完成，不接受 HTTP 请求提供的免核对标记。目标 `checks.passed` 且不是 `legacy-unreviewed` 时，比较版本的 `materialSnapshot` 与当前原始 `site.materials` 文本；有效用户补充沿用目标版本不可变的请求链。新版本在完整事实核对后保存原始资料快照；局部修改仅在父版本有同源核对依据时保存可复用快照，翻译继承中文的核对依据。旧版本缺快照时，仅有完整的初次生成记录（首版、初始修订、版本关联、请求原文一致、成功 facts 调用）才可还原依据；其余情况保守重核，不补写历史版本。资料变更后重核仍使用原有恢复资料链。
- 可沿用时，`checkSiteCode` 仍清理并跑全部确定性检查，只略过模型事实调用；新版本 `checks.factReviewFrom` 保存目标版本编号、ID 和原核对时间，工作台与版本历史显示「沿用 vX 的事实核对」。再次恢复沿用过的版本保留最初核对时间；检查失败不存版本。来源不确定、未核对的导入或资料不同仍走既有模型核对，恢复的整版本沿用规则独立于核对段复用，不接受客户端免核对参数。
- 版本历史直接读取工作台状态中的完整版本；左侧按 1 分钟、10 分钟、1 小时或本地日期分组，最新版本在前，每条显示版本号、时间、作者、摘要、检查状态、名称和当前版本标记。分钟、10 分钟与小时桶按当前本地时间实例减去桶内经过的时间，保留不同 UTC 偏移；纽约夏令时回拨后的两次 01:55 不合并，分组标题显示偏移。本地日期仍合并为同一天。右侧用已有 `code-preview` 沙盒显示选中版本各页，可切中英文与 1440/768/375。名称通过 `PATCH /api/sites/<siteId>/versions/<versionId>` 保存，最多 80 字，空串清除；只修改元数据，不改代码、检查记录或当前修订号。指定恢复使用已有 `history/restore` 入口。
- 未点选区块的对话修改先把用户请求、当前版本编号及版本目录（编号、名称、摘要、时间、作者，不含代码）交给模型。模型在结构化 `referenceRevisions` 数组中声明参考编号，普通修改可为空；系统不从消息做正则解析或型号判断。字段结构或编号形态非法时显示简短中文提示，不把 Zod 英文细节交给用户；任何编号不存在都会结束当前后台任务，在进度与对话中说明原因。两类失败均不调用写作、不保存版本。合法版本 ID 保存在运行记录中，完整旧代码作为不可信数据交给首次写作；同时携带当前代码，要求只取回用户指定部分并保留其余部分，事实仍以当前有效资料为准。底线拒收后的最多两轮局部修正只拿拒因对应片段与当前有效资料，不再发送历史整站。结果经 `commitSiteCode` 检查后存为新版本。区域验收按用户是否点名页面区分：点名时仅该页指定区域可变；未点名页面的“产品区”可包含各页产品区及首页产品入口，页头页脚、其他区块、联系页等范围外始终保持。范围外整段规范化 outerHTML 包含 href 与所有属性，自动生成的预览版本参数单独归一化；范围外每个可交互元素滚入视口后，核对 `checkVisibility({checkOpacity:true,checkVisibilityCSS:true})`、布局矩形宽高非零、中心 `elementFromPoint` 命中自身或后代三项结果在前后版本一致，观察后恢复滚动位置；不能只比自身样式或文字证明功能保留。`tests/t129-version-history-check.test.ts` 经真实 CLI 与 Chrome 检查祖先隐藏导航/询盘、错误链接和禁用询盘指针的负例，由 `npm test` 自动包含。存版与底线检查通过不替代该范围核对；真实模型能力不以受控 HTTP 测试代替。
- 全部站点页和列表 API 的名称、公司名、更新时间读取代码站点记录的 name、updatedAt，并按该更新时间排序；不写入旧草稿。失败导入与上传保护条目从相同存储读取元数据，不回到旧渲染层。
- 预览通过本站 `code-preview` API 渲染当前或指定版本，language=en 读取英文；中英发布路径为 /published/<siteKey> 与 /published/<siteKey>/en，都只读同一个代码记录并用同一静态渲染器。只有英文存在时系统在页头之后加语言切换链接；目标语言没有对应页时切换到该语言首页。当前或指定版本、语言或页面不存在时明确返回 404。iframe 与响应 CSP 都禁脚本和外部资源；工作台预览允许同源读取以定位区块，发布响应仍为不透明来源；允许系统询盘表单提交，表单复用现有询盘入库接口。T-128 不验收外部邮件送达。

## 5. 旧演示站导入

T-145 的离线导入 CLI 只处理批准的导出数据，代码仍经过 commitSiteCode。中文 home 保留原单页全部区块与顺序，不拆成假独立页面；原英文留在归档与源 JSON，不增加英文功能。清理与三档确定性检查均执行，唯有模型事实校对不调用，明确标记「旧站转换未做模型校对」，作者显示「旧站转换」。源材料和从源数组得到的结构计数不是模型事实校对结果。

不通过的候选不存版本，只保存「旧站转换失败：原因」元数据；列表与打开显示同一原因，无默认草稿或伪造预览。缺少 main 内的 h1 属于候选结构失败，由提交入口存失败条目，CLI 继续处理后续站点，批次以失败退出；浏览器没有载入 HTML 等执行故障仍明确报错。含用户上传且未转换的记录显示「旧站点未转换，含用户上传，已保留」。已有代码记录和失败元数据均不覆盖；失败重跑仍报告失败。首次记录采用不可覆盖的完整文件发布，单站导入会话使用固定站点内标识，重复或中断的执行不重复建版本、会话。

正式导入与清理之前，在 worktree 的只读副本验证，再由主控逐项确认精确路径；源演示 JSON、上传保护站和全部新路线数据保留。系统没有定时清理或产品清理开关。

## 6. 质量、数据与执行边界

评估入口为 npm run eval:new-route：固定七家模拟公司与精密工程、现场实拍两种风格。快速档每家一种风格，只生成首页和产品页；餐饮、培训、设计分别为首页与菜单、课程、作品页，只与同档同资料比较。review/mixed 与 review/company 分别交不同的新盲评实例，跨轮比较在独立 comparison-review；private 的映射、用量、来源和跨轮身份由主控保存，不交评审。技术通过不能替代独立审美判断；失败轮次、未知用量如实保留。

站点记录、完整版本、资料和运行在 FS；会话、线索与批注保持既有 FS/PG 契约。原生 PostgreSQL 站点版本存储不在 T-145 范围。验证和离线导入可用进程环境 SITECRAFT_DATA_ROOT 指定数据根目录，默认项目 .sitecraft-data；HTTP 请求不能修改它。密钥仅进进程及被忽略的本机环境文件，不进入代码、文档、模型输入、响应或截图。

模型使用 deepseek-flash。普通生成、修改与恢复做模型事实校对，局部修复最多两轮，不自动重发失败模型请求，不回到旧路线。询盘仅在用户资料或要求明确出现时提供，不默认增加预约，不扩充系统部件；营业时间、地址和价目按资料用普通 HTML 展示。表单复用线索入库，邮件送达没有实测时不宣称通过。

验收按 AGENTS：相关测试、typecheck、全量 test、build、Chrome 1440/768/375 本次截图与提交入口底线结果、独立审核。执行者自查不是盲评，不自动删数据或扩展部署、实机范围。
