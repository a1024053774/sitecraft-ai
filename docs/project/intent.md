## 1. 目标与当前交付

帮助中小企业用企业资料和对话生成美观、内容可信、可持续修改的网站。重点是行业适配、品牌差异和真实业务表达，而不是增加模板数量或堆叠动效。

首批业务重点是工业、设备、零部件、外贸 B2B 企业官网与产品展示。资源研究应覆盖更多行业和主题，不把产品永久限制在这一类企业。

Q8 选择“内部验证、按未来自助平台设计”；Q15 进一步明确近期交付为**内部技术 Demo**，由项目负责人扮演用户、使用明确标记为模拟的多行业公司资料测试。真实客户试点和公开自助上线均不作为本阶段验收条件。

## 2. 已确认的用户输入与行为

- 输入包括公司简介、产品或服务表、图片、联系方式、主要行动目标与品牌偏好；尚不存在的事实不能编造。
- 页面规划以用户明确要求为先；未列出页面时由模型依据需求规划；仅无法确定时使用首页、产品/服务、联系的默认方案。不是固定三页，也不能擅自忽略用户指定的页面。
- AI 自动产出初稿。模板、重大视觉方向与发布前需要用户确认；普通修改展示修改前后差异并可撤销。
- 站点中英文一起生成（2026-09-24 负责人确认）：英文与中文出自同一份资料，同时写入、同时撤销；资料没有的内容，中文写「待补充」，英文写 `To be provided`，标题和正文都缺的条目不在访客页显示。只有默认英文的旧草稿，在补齐英文前不对访客提供 EN 切换。
- 配色以「色彩集」给用户选（2026-09-24 负责人确认）：首批 6 套（青花瓷、石墨工坊、工程暖橙、铜锈、松石、莫兰迪），每套在每个样子里各调一份色板；也支持用户输入品牌主色或从 Logo 取色，由固定规则生成整套并检查对比度。样子和配色都在聊天里选，输入框上方有「样子」「配色」按钮可随时换。
- 生成前允许像 AI 生图一样选择视觉方向：预览示意和普通语言，不向用户展示 Skill 名称。卡片按手头能落地的样子分类，不锁死四张，也不按行业 1:1 绑死模板。
- 页面结构由模型从 SiteCraft 区块库里挑选区块和变体，样子是一套设计 token；模型还可以写受限的站点样式（只作用于站点区块、经校验、可单独撤销、三档宽度检查不过就拒绝），不写 HTML 和文字（2026-09-29 负责人确认，T-048，取代 Q27=A 中模型不输出 CSS 一条）。开源模板、区块和样式是移植进区块库的素材，由**一个**共享预览引擎组这家公司的页面；不是整页挖空填词，也不把未经移植的外部区块直接拼进页面，也不另写第二套渲染器。
- 内部工具或 Skill 与风格没有一一对应的产品承诺；同一种样子可由不同经验证的内部流程完成。当前内部文案/版式规则定为 `sitecraft-frontend-less-ai-tone`（`skills/sitecraft-frontend-less-ai-tone/`，运行时 `sitecraft-frontend-less-ai-tone@0.3.2`；P4 冻结基线 `@0.2.0`），名称不出现在用户选项里。
- 扩充不同主题、适用范围的开源模板，并利用现有模板。此前 top5 是已有优先复核清单，不再是候选池上限；“只做 forge + 一套模板且不找新来源”的建议未被接受。

## 3. 内嵌的需求对齐（新建站点默认开启）

这是本次新增的高优先级能力：把 grilling 的“理解需求—提出有限选项—等待回答—继续推进”融入产品 Agent 的会话流程。

- 需求对齐（2026-09-24 负责人确认）：**新建站点（还没生成过）默认开启**，已生成的站点修改时不重问完整需求，只在换样子、加页面这类重大变化时确认；输入框上方常显需求对齐开关，可随时关闭（2026-09-29 负责人要求从「+」菜单移出）。形态参照 harness 向用户提问：一张卡一次问 1–4 题，全部答完一次提交，最多 3 轮。
- AI 只对尚未明确、会影响建站结果的问题提供可点选项；已提供资料不重复追问。
- 用户选择后直接提交选择结果，Agent 在同一会话继续；不要求复制 AI 输出、不要求手打“继续”。
- 等待期间保留任务、问题和答案；刷新、断线后仍能看到待回答问题，而不是重新开始对齐。
- 展示的是问题、选项、简短理由和结论，不展示内部推理文本。
- 关闭需求对齐只关闭完整访谈流程，不关闭风格入口，也不关闭事实核验、必要澄清和发布确认。

默认开启范围、每张卡题数和轮数已于 2026-09-24 确认；选项标签和具体恢复协议仍属设计建议，详见 spec。

## 4. 质量验证

Q12 已确认先做 **3 个行业 × 1 份资料简报 × 4 个流程组，共 12 个结果**；有稳定差异再扩到 24。

- A：当前默认流程；B：增加一个审美主流程；C：再增加行业/模板适配与设计约束；D：再增加截图审查和有限局部修复。
- 各组固定相同模型版本、企业资料和可用素材；记录整体流程的效果，不能把 C 的全部收益归因于单个因素。
- 使用内部模拟企业可验证工程行为和视觉偏好，不能据此声称真实客户满意度、行业真实性或转化率提升。
- 生成事实与资料核对，使用真实浏览器看桌面/平板/手机效果；隐藏分组并打乱展示顺序，由独立审核 agent 评价行业匹配、差异感、可读性、图文一致与主要行动（2026-09-26 负责人决定：盲评和审核不由负责人做，见 T-013）。
- 做这项工作的 agent 自查可以找问题，不能宣布审美通过。数值阈值尚未校准。
- 模拟资料加厚（2026-09-24 负责人确认）：模拟公司资料包补上规格参数、应用行业、加工能力、认证状态等设定，资料包内明确标为模拟；资料包没写的仍是「待补充」。模拟包可附许可已核的工业产品照片（逐张记录来源、作者、许可，CC0、公有领域、CC-BY、CC-BY-SA，CC-BY 类在访客页署名），按真实用户上传产品图的路径进入草稿；这些照片只属于模拟资料，不进生成器素材库或 `vendor/`。照片内容必须与产品一致，许可对但拍错品类的图不得使用，该品类回退到标注「示意」的示意图。
- 2026-09-18 负责人盲评 **不过**。12 格分数已写入本机 `localStorage`（`sitecraft-quality-scores-p4`）。否决点：主题与行业不符、Logo/站点名仍是模板品牌、未声明壳（客户 Logo 墙、SaaS 定价、ScrewFast 字标、演示图）原样留下。首屏缩略图不能当整页验收。Q26=B 已确认：成品不得再靠挖空填词。在生成路径改完前不要扩到 24 组。

## 5. 数据、模型与配置

- 当前使用 DeepSeek API，模型名 `deepseek-flash`（V4.1 Flash，对话与看图同一条）。允许将企业资料和图片发送到第三方模型；只发送当前任务所需资料，不包含密钥、无关项目配置或内部凭据。
- 质量优先，当前不设成本或生成时延 KPI；仍应记录耗时和 token，保留取消、请求超时和有限修复次数，避免无限执行。
- 数据采用 2026-09-18 用户决定（Q17=A 已取代）：删除须由用户明确选择；系统不得替用户主动删除对话、草稿、上传或站点。不实现 90 天自动清理，也不保留可暂停的自动清理开关。已发布站点仍由用户控制，不得静默删除。
- 用户要求将既有 `env.md` 的 base URL 和 API key 用作本项目独立配置，不建立软链接。
- 本轮读取核验：三份来源的文本 DeepSeek 字段一致；项目 `.env.local` 已包含对应 `DEEPSEEK_BASE_URL`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`。Git 模式为普通文件 `100644`，已被忽略且未跟踪，因此无须重复复制或询问来源路径。本轮没有更改凭据，也没有发起新的模型请求。

## 6. 延续的工程边界

- 只在自己的 fork 开发；PR #4 是能力参考，不整体合并。
- 保留模板来源版本和本地构建方式，不提交全部上游 dist。
- 现有模板可复用但必须检查渲染、内容落点和素材授权；代码开源许可不覆盖所有演示图片、字体或商标。
- 原生 React 模板和 shadcn/Radix 的系统性改造仍留在后续决策门。现有 iframe 是实施现状，不是审美一定优秀或未来不能改变的证明。
- 当前草稿修改仍走 `commitOperations`。安装开发 Skill 不代表运行时自动具备能力；须有具体消费者、可验证输出和版本记录。
- 当前工作树已有会话、意图及测试修改，先核验再计为已完成；不覆盖或重排无关用户变更。验收后按独立模块提交并推送到自己的 fork。
- 协作不绑定特定模型；主负责人负责拆分与整合、核对结果并提交/推送。持续任务使用当前 harness 的 Goal/任务机制或项目计划记录，不把某一种任务工具当成产品能力。
