## 1. 目标与当前交付

帮助中小企业用企业资料和对话生成美观、内容可信、可持续修改的网站。重点是行业适配、品牌差异和真实业务表达，而不是增加模板数量或堆叠动效。

首批业务重点是工业、设备、零部件、外贸 B2B 企业官网与产品展示。资源研究应覆盖更多行业和主题，不把产品永久限制在这一类企业。

Q8 选择“内部验证、按未来自助平台设计”；Q15 进一步明确近期交付为**内部技术 Demo**，由项目负责人扮演用户、使用明确标记为模拟的多行业公司资料测试。真实客户试点和公开自助上线均不作为本阶段验收条件。

## 2. 已确认的用户输入与行为

- 输入包括公司简介、产品或服务表、图片、联系方式、主要行动目标与品牌偏好；尚不存在的事实不能编造。
- 页面规划以用户明确要求为先；未列出页面时由模型按资料能撑起的内容规划，资料少就做得少，用户补充后再继续丰富。不默认加联系页、询盘表单、报价或样品入口、邮箱联系；用户资料或要求里有才做（2026-10-09，T-141）。不能擅自忽略用户指定的页面。
- AI 自动产出初稿。重大视觉方向与发布前需要用户确认；普通修改展示修改前后差异并可撤销。
- 英文版（T-127、T-151）：先只生成中文站，通过底线检查后询问是否满意、由用户点「生成英文版」。非思考模式逐页只翻译文字节点、页面标题与可见属性，结构、CSS、图片和系统部件保留；资料没有的内容固定为 `To be provided`。完整版本同时保存中英，预览与版本历史可切语言，发布英文使用独立路径。中文修改后提示英文版落后并标明基于中文第几版，不自动重译；用户点「按当前中文版重新翻译」才更新，撤销与恢复沿用完整版本机制。含数字记号、邮箱和网址在对应段内按多重集合机械对照，不比顺序；纯字母缩写视为译词，已登记完整单位别名先按最长匹配读取，再识别时间比率；数值与完整单位只作确定的等价换写，不换算单位制，未知单位原记号比较；时间比率按年/月/日/时/分五类确定等价并绑定对应数量，不跨类换算，计数与物理单位继续核对；省略整数位小数和中文数字数量同样保护，CSS 生成文字也参与核对。含数字型号和单位运算符记号先独立抽取；纯计数量词仅按显式小表归一为同一数字，英文后续词须纯字母、无运算符且不属于显式单位词表；英文槽位中记录公司名及资料明确英文名子串原样保留，其余全角标点由代码转换为半角。底线修正只发被拒段的原文、当前译文与拒因，不整页重译，不增加原文没有的数字。公司名只用站点记录名称或资料明确声明的英文名，不猜正文子串；没有明确英文名时沿用中文名并说明可补充后重译。翻译面向海外 B2B 采购，不添加材质、等级或认证，不加强承诺；系统表单用 Inquiry / Send inquiry 与半角英文标点；中英版本共用系统底图的三档静态素材和 MIT 许可，系统抽象说明按语言呈现。不另做英文模型事实校对。专有名词及语义是否译准仍是 T-082 的已知限制。
- 生成前让用户选风格（2026-10-07，T-127）：主风格单选，另有「版式：规整 ↔ 大胆」「信息：疏朗 ↔ 紧凑」两个滑杆，默认「帮我选」由模型按行业挑；风格卡用本系统真实生成的缩略图和普通语言，不向用户展示 Skill 名称。每个风格对应一份风格 skill，核心规范 skill 每次默认加载。
- 模型直接写站点代码（2026-10-07 负责人决定，T-127，取代 T-048）：版式、结构、文案由模型按资料和所选风格决定；harness 负责版本库（每次修改一个完整版本，可恢复）、唯一提交入口、底线检查和评估。修改方式放开：对话、预览批注、快捷按钮都由模型直接改代码。
- 核心规范与用户选定的风格 skill 引导版式、事实和文案；内部 Skill 名不作为用户选项。结构与文案由模型根据资料决定，不依赖模板或固定区块。

## 3. 内嵌的需求对齐（新建站点默认开启）

这是本次新增的高优先级能力：把 grilling 的“理解需求—提出有限选项—等待回答—继续推进”融入产品 Agent 的会话流程。

- 需求对齐（2026-09-24 负责人确认）：**新建站点（还没生成过）默认开启**，已生成的站点修改时不重问完整需求，只在换样子、加页面这类重大变化时确认。形态参照 harness 向用户提问：一张卡一次问 1–4 题，全部答完一次提交，最多 3 轮。
- AI 只对尚未明确、会影响建站结果的问题提供可点选项；已提供资料不重复追问。
- 用户选择后直接提交选择结果，Agent 在同一会话继续；不要求复制 AI 输出、不要求手打“继续”。
- 等待期间保留任务、问题和答案；刷新、断线后仍能看到待回答问题，而不是重新开始对齐。
- 展示的是问题、选项、简短理由和结论，不展示内部推理文本。
- 关闭需求对齐只关闭完整访谈流程，不关闭风格入口，也不关闭事实核验、必要澄清和发布确认。

默认开启范围、每张卡题数和轮数已于 2026-09-24 确认；选项标签和具体恢复协议仍属设计建议，详见 spec。

## 4. 质量验证

质量以独立评审判断换公司不像同模板、新旧成对选择新版为准；混排识别只作参考（T-143）。固定资料与风格经真实入口生成，保留底线检查、失败、用量与截图，盲评实例互相隔离；执行者自查不代表审美通过。

模拟资料保留模拟标注、事实与缺口；照片逐张核来源、许可和题材一致性，CC BY 类在访客页署名。模拟资料和照片不成为自动加载的模板库。模拟邮箱用负责人自有 luckye.online 域名，缺口保持「待补充」，不为评审隐藏；不能从内部测试推导真实客户满意度或转化率。

## 5. 数据、模型与配置

- 当前使用 DeepSeek API，模型名 `deepseek-flash`（V4.1 Flash，对话与看图同一条）。允许将企业资料和图片发送到第三方模型；只发送当前任务所需资料，不包含密钥、无关项目配置或内部凭据。
- 质量优先，当前不设成本或生成时延 KPI；仍应记录耗时和 token，保留取消、请求超时和有限修复次数，避免无限执行。
- 数据采用 2026-09-18 用户决定（Q17=A 已取代）：删除须由用户明确选择；系统不得替用户主动删除对话、草稿、上传或站点。不实现 90 天自动清理，也不保留可暂停的自动清理开关。已发布站点仍由用户控制，不得静默删除。
- 密钥只放被忽略的本机环境文件或加载进进程，不建密钥软链，不重复复制凭据。
- T-145 已按主控确认的精确清单导入 13 个旧演示站中文 home 并清理测试残留，旧英文归档；事实状态明确未做模型校对。失败只存元数据，不伪造站点。4 个上传保护站及已有新路线数据保留；主数据执行结果见 T-145 Resolution，本次授权不改变删除须由用户明确选择的规则。

## 6. 延续的工程边界

- 只在自己的 fork 开发；PR #4 是能力参考，不整体合并。
- 核心规范、风格、照片和系统图标分别保留来源与许可；代码许可不覆盖图片、字体或商标。
- 原生 React 模板和 shadcn/Radix 的系统性改造仍留在后续决策门。现有 iframe 是实施现状，不是审美一定优秀或未来不能改变的证明。
- 所有站点修改走同一个提交入口并存成版本（T-127）。安装开发 Skill 不代表运行时自动具备能力；须有具体消费者、可验证输出和版本记录。
- 保留无关用户变更。执行者一张票一个本地提交，不推送；主控负责验收、整合和推送。
- 协作不绑定特定模型；主负责人负责拆分与整合、核对结果并提交/推送。持续任务使用当前 harness 的 Goal/任务机制或项目计划记录，不把某一种任务工具当成产品能力。
