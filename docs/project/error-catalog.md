# SiteCraft 用户可见错误目录

内部接口保留稳定 `error`/`code`，界面只显示 `userMessage` 和可行动的恢复建议。错误不会绕过版本保护、强制覆盖草稿或把未校验的模型输出写入页面。

| 内部码 | 触发条件 | 数据是否保存 | 用户提示与下一步 |
| --- | --- | --- | --- |
| `revision_conflict` | 请求携带的草稿版本落后，或模型处理期间版本发生变化 | 当前修改不保存；最新草稿返回给前端 | 已载入最新版本；保留输入和选择，检查后重新提交。旧方案不会自动应用 |
| `stale_question` | 旧标签页提交了过期问题/确认版本 | 答案不保存 | 使用当前问题卡片；刷新读取同一会话 |
| `conversation_not_found` | 会话不存在或被删除 | 不创建新草稿 | 重新开启需求对齐并提交原 Prompt |
| `alignment_pending` | 会话仍等待回答、生成或确认 | 不重复生成 | 继续当前问题、确认方案或关闭对齐 |
| `invalid_payload` / `invalid_option` | 缺少字段、选项不属于当前问题 | 不保存 | 检查当前问题和补充说明 |
| `not_configured` | 模型密钥或模型名未配置 | 不伪造修改 | 配置模型后重新提交 |
| `timeout` / `provider_error` / `invalid_output` | 模型超时、服务异常或结构化输出不合法 | 不自动覆盖草稿 | 先读取状态，再按提示重试；未经校验的内容不会写进页面 |
| `truncated` | 模型的回答达到 token 上限被截断（推理 token 也计入上限），不再重试 | 不改动草稿；需求对齐的问题和答案保留 | 这次生成被截断，没有改动草稿；可以直接重试 |
| `operation_error` | 受控 operation 校验或保存失败 | 草稿保持原版本 | 读取最新草稿后再试，不确认旧方案 |
| `image_invalid` | 图片格式、大小、来源、许可证或归属不符合 | 图片不进入成品 | 上传有效图片并补齐来源、许可、作者和站点用途 |
| `lead_invalid` | 访客提交的询盘缺姓名、邮箱或需求说明 | 不保存 | 询盘内容不完整；检查后再提交 |
| `lead_not_found` | 询盘指向的站点不存在 | 不保存，不创建空站点 | 返回站点发布页后重新提交 |
| `lead_full` | 该站点的询盘收件箱已满 | 不保存 | 先处理已有询盘，再接收新的留言 |
| `smtp_error` | 询盘已入收件箱，但邮件转发失败 | 询盘已保存 | 在收件箱确认留言，再检查邮件服务配置 |
| `delete_unconfirmed` | 删除站点时没有输入正确的站点编号确认 | 不删除任何数据 | 输入当前站点编号后再确认 |
| `site_not_found` | 打开的站点不存在或已被用户删除 | 无变化 | 返回站点列表，打开仍存在的站点 |
| `database_error` | PostgreSQL/文件存储读写失败 | 结果未知时以回读为准 | 刷新读取草稿或收件箱后再试 |
| `network_error` | 网络中断、响应不完整 | 结果未知时以回读为准 | 刷新并回读，再决定是否提交 |

## 版本冲突原则

`revision_conflict` 是并发保护信号，不是可忽略的前端异常。客户端收到 409 时必须采用服务端返回的最新草稿，保留本次 Prompt/选择供用户重新提交；依赖旧版本生成的 proposal 不得自动重放。需求对齐的回答阶段不增加草稿 revision，只有用户确认并成功执行 `commitOperations` 才会增加 revision。
