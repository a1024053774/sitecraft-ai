## 要做成什么样

内部 Demo：用模拟的工业、设备、零部件、外贸资料，做出看起来像那家企业自己建的网站。行业对得上、版式有差异、事实不编、预览里改完能看见、对话可以停下来再继续。

公开上线、真实客户试点、整仓合并 PR #4、让模型写 HTML 或文字，都不是本阶段。

数据删除按 2026-09-18 用户决定（取代 Q17=A）：删除须由用户明确选择；系统不得替用户主动删除对话、草稿、上传或站点。不实现 90 天自动清理，也不保留可暂停的自动清理开关。已发布站点仍由用户控制，不得静默删除。

## 页面怎么生成

1. **样子**：用户选一类能落地的视觉方向，不是选行业名，也不是选 Skill 名。卡片数量不锁死为 4；只挂手头已有本地快照、许可可核的模板。行业来自资料。
2. **模块**：在同一视觉族里，按业务挑选要出现的区块（首屏、产品、关于、联系等）。壳（导航、页脚、色板、栅格）跟这一族走。禁止把 A 站 Header 接到 B 站 Features 上。
3. **成品**：生成站必须是这家公司的页面。开源模板、区块、样式和提示词是**素材**（结构、token、许可资产、写法），不是「只当样子参考」，更不是把整页快照挖几个槽当交付。

已废弃的成品规则：只改声明槽位，未声明节点保持原样。那是挖空填词。P4 盲评里 Airbnb Logo 墙、ScrewFast 字标、`$29` 套餐留下，就是这条规则的结果。

组页方式（2026-09-29，[T-048](../../.project-map/tickets/T-048-generation-direction-block-library-css.md)，取代 Q27=A 里「模型不输出 CSS」和「一个样子一份 overlay」）：SiteCraft 自有**区块库**（开发侧写 HTML/CSS，每种区块 2–3 个变体，写明读哪些草稿字段、最少要多少资料、三档宽度怎么排）+ 每个样子一套**设计 token** + **一个**共享预览引擎。页面编排是草稿里的数据，模型通过 operation 选区块、变体和顺序。用户明确提出外观或版式要求时，模型才可以写一份**站点样式**：限定作用于站点区块、经校验的 CSS，加不进文字、外部资源和固定定位，有大小上限，每次是一个可单独撤销的 operation；整站生成和需求对齐不自动套用站点样式，也不向模型推荐站点样式方向。提交前按 375 / 768 / 1440 渲染检查横向溢出和文字重叠，不过就拒绝并说明原因。模型不写 HTML 和文字。草稿仍只走 `commitOperations`；adapter 仍是可审查数据。禁止另起第二套渲染器，本阶段不做原生 React/shadcn 拼装。

迁移：四个生产样子均由区块库拼页，统一经过三档检查、对照和独立盲评。验收除盲评外，还要同一个样子换两家公司后能看出差异。工程工业已经迁完（T-053）：页面由区块库拼出（`lib/blocks/`），旧 overlay 已删，也不依赖 vendor 里的 ScrewFast 快照；除默认布局外另有首屏「大标题加参数条」、产品「按类别分组」「参数对比表」、询盘「联系条」四个不靠照片的布局，各有最少资料条件；产品「型号索引表」（T-073，区块素材流水线的第一个布局，要至少 3 个产品，所有样子可选，简介和第 4 项以后的参数收在每行下面整行宽的折叠详情带里）经 AI 味审查后进库；合作方式「纵向流程」（T-074，一步一整行，无额外资料条件，所有样子可选）同样经审查进库；首屏「目录封面」（T-074，右侧是产品系列目录，要至少 2 个产品，所有样子可选）同样经审查进库；认证「证书状态表」（T-074，一证一行、状态单独成栏，无额外资料条件，所有样子可选）同样经审查进库；商业条款「左右条款」（T-080，区块标题在左、条款在右）和「条款带」（一条一格的横带，只有一条时整带放这一条）无额外资料条件、所有样子可选，同样经审查进库。商业条款区块（T-079）已加入四个样子的默认页面，按固定双语种类名和资料值逐行显示，无条款时整块隐藏。明亮产品也已迁完（T-055）：沿用共用区块和 token，另加行业/能力卡片、步骤卡、展开问答、面板询盘四种布局（所有样子可选），合作方式步号由共享区块显示，旧 overlay 已删。蓝白目录也已迁完（T-056）：默认产品为目录行，并排的应用行业/加工能力统一布局、步骤卡按条数均衡分行，旧 overlay 已删。灰底短路径已迁入区块库，旧 overlay 已删除（T-057）。

草稿新字段（2026-10-03，[T-078](../../.project-map/tickets/T-078-new-draft-fields-for-content-blocks.md)）：资料里有、草稿原来没有专门位置的内容改为结构化字段，第一批是商业条款（MOQ、交期、产能、贸易条款等）和设备（稳定 id、双语名称、数量、规格），第二批是质检流程和沿革。模型只按资料抽取，资料没有的条目不出现；条款名、字段名用固定双语词典；设备事实按 T-079 同句原文子串与数量紧邻名称规则核对，英文按 T-082 做数字/代码/单位机械核对；加工能力是工序、设备是机器，不能重复；访客页事实检查覆盖新字段；布局走区块素材流水线。

验收否决：未选用的模板品牌、客户 Logo 墙、SaaS 定价、演示图、假评价数字不能出现在生成站上。只改标题而留下 ScrewFast / Airbnb / `$29` 不算做成。`missing` 是落点失败，不是允许演示壳留下。

文案去 AI 味和版式去 AI 味走同一条生成路径。内部规则用 `sitecraft-frontend-less-ai-tone`（`skills/sitecraft-frontend-less-ai-tone/`，运行时 `@0.3.1`；P4 冻结基线仍是 `@0.2.0`）。只有用户提出外观要求时，模型才能写受限的站点样式；整站生成和需求对齐不自动写样式。不写 HTML 和文字。草稿仍只走 `commitOperations`。访客页说明类文字不写只交代缺口的句子和建站元话术（T-045）。

需求对齐卡里的色块只从当前视觉族 adapter 的 registry 色板派生；模型返回的颜色值不能覆盖页面实际使用的色板。

发布页正文硬门（T-089）也属于区块库成品约束：`visitor-layout-scan.js` 按实际前景色和合成后的纯色背景测正文 4.5:1（大号文字 3:1），图片背景无法测量时报告「未测」并拒绝；正文段落按渲染 Range 检查中文约 40 字、英文约 75 字单行上限，参数表、按钮、型号、邮箱和导航列为豁免。目录 Hero 使用可测的实色面，族 token 的 muted 值须在浅色能力面上通过 4.5:1。

## 素材怎么用

开源仓库、本地快照、Jiro 免费区都是可审查素材，不是成品。代码 MIT 不批准图片、字体、图标或商标。调研不等于准入，也不等于已经能生成。

2026-09-18 会话 `d55f6e7c-b51f-491f-bb6f-5f14cf955f6a` 的目录/工业检索：外贸侧优先核 Nordic-Store、Start Bootstrap Shop Homepage、bbulakh/tailwind-ecommerce；制造业公开整页很少，AstroFlow 可试。细节和排除项见研究报告。未克隆、未构建、未准入。

## 参考站和提示词怎么用

Jiro 最大的架构课写在它自己首页上：**跨源把 Header 和 Features 硬拼，每一块会像另一个网站。** Chrome 商店还补了一句：先贴一次 Master Prompt，后面每块才共用同一套 token。对我们来说，Master Prompt ≈ 先锁 `visualBrief` 和族 token，再组该公司页面。

免费整页气质不像工业，**提示词仍要看**：怎么锁一族 token、怎么写单块、怎么警告 Inconsistent Sections。学写法，不因皮不对就丢掉。Copy Prompt 不当生产提示词，也不提交进 `vendor/`。

2026-09-17 对照 [免费组件](https://jiro.build/components/free)、[免费模板](https://jiro.build/templates/free) 和工业分类后的用法：

- **学形态**：按 Header / FAQ 分区浏览 ≈ 模块选择；Collection 名是视觉族，不是行业名。
- **借结构**：克制的分栏、手风琴、三步/四步流程、询盘表。配方表见 [plan-history.md](./plan-history.md) 的「Jiro 怎么用」。接到**已准入、同一视觉族**的素材上，颜色跟当前族走。
- **工业/外贸整页**：KonsTuck、Lozitick 全是 Premium。只借「这一类站该有哪些区块」的清单。不买、不搬橙底工地皮和飞机图。
- **不用**：把免费六张整页当工业样子卡；Premium 源码；jiro MCP 进生成运行时；Copy Prompt 当生产提示词；把提示词或缩略图提交进 `vendor/`。

条款页仍 404。生成器再分发许可 unknown，所以只当内部 Demo 的配方，不能当成 MIT 素材库。
