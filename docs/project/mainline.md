## 要做成什么样

内部 Demo：用模拟的工业、设备、零部件、外贸资料，做出看起来像那家企业自己建的网站。行业对得上、版式有差异、事实不编、预览里改完能看见、对话可以停下来再继续。

公开上线、真实客户试点、整仓合并 PR #4，都不是本阶段。

数据删除按 2026-09-18 用户决定（取代 Q17=A）：删除须由用户明确选择；系统不得替用户主动删除对话、草稿、上传或站点。不实现 90 天自动清理，也不保留可暂停的自动清理开关。已发布站点仍由用户控制，不得静默删除。

## 页面怎么生成

2026-10-07 起（[T-127](../../.project-map/tickets/T-127-route-model-writes-site.md)）：**流程固定，内容放开。**

已合并的 [T-128](../../.project-map/tickets/T-128-new-route-tracer.md) 提供中文站点代码、底线检查、完整版本、对话修改与撤销、刷新恢复。[T-129](../../.project-map/tickets/T-129-version-history-panel.md) 提供版本面板、命名、指定版本恢复和对话「改回某版」：模型按版本目录声明参考版本；用户未限定页面时「产品区」包括首页产品入口，点名页面时只改该页。截图打磨、模板味检测、批注与英文版仍是后续范围；实现细节见 [spec.md](./spec.md) 第 4 节。

[T-130](../../.project-map/tickets/T-130-eval-set.md) 提供 `npm run eval:new-route`：四家模拟公司 × 两种风格经真实入口生成整站，保留每轮拒收原因、截图与用量，产出两种 T-104 盲评任务及跨轮成对比较。真实运行及第一轮独立盲评是否完成，以票的 Resolution 为准；拒收和外部阻塞不能写成页面质量通过。

[T-133](../../.project-map/tickets/T-133-floor-check-false-rejections.md) 将每轮候选代码（含被拒的）及图片上传证据保存在评估轮次的 `private/case-N/`，不依赖 worktree 数据。手写数字全部按事实来源检查；核心规范引导步骤和列表用原生 `ol` 或标准 CSS counter 编号。「待补充」占位不当新事实，真实数量、条件、范围、对象与承诺政策仍须有资料依据。

1. **生成层**：模型直接写站点代码：每页一份 HTML、公共页头页脚、一份 CSS。版式、结构、文案按资料和风格决定。
   - **核心规范**每次加载：读懂公司和访客、事实只来自资料、版式不重复、图片跟内容走、色彩字体纪律、文案口吻、技术底线。来源：taste-skill（MIT）、Impeccable 的 craft floor（Apache-2.0）、本项目两份去 AI 味 skill、历次盲评的反面清单。
   - **页面骨架**版式卡与核心规范一起加载：每次规划随机排列并记录顺序，模型按资料厚度、访客任务与授权图片选结构起点，说明选择及不选次合适那张的理由；可调整或以 custom 另创，不按行业或风格写死。产品族入口只适用于至少三个差别明显系列且以目录为主的资料。卡片只给原创结构建议，不包含参考官网的文案、代码或视觉资产；质量结论以 T-135 评估及独立盲评为准。
   - **风格**由用户选：主风格单选 + 「版式：规整 ↔ 大胆」「信息：疏朗 ↔ 紧凑」两个滑杆，默认「帮我选」。风格卡展示本系统真实生成的缩略图。每个风格一份短 skill，必须能在评估集里看出差别，看不出就删。
   - 步骤：读资料 → 页面大纲（可给用户看）→ 写页面（页面可并行）→ 检查修正 → 看截图打磨 → 存版本。
2. **Harness 层**：
   - **版本库**（照 Notion 页面历史）：每次修改存一个完整版本；撤销/恢复都生成新版本；版本面板左侧按时间分组列出（作者、一句话摘要、检查状态、可命名），右侧预览并可恢复。对话修改由模型读取版本目录、结构化声明参考编号，系统校验后取旧代码给写作步骤；不靠解析用户消息判断版本。
   - **唯一提交入口**：生成、对话、批注、手改、恢复都经过：清理脚本和外部资源 → 底线检查 → 存版本。CSS 生成文字从渲染后的列表类型和伪元素 content 读取，与 HTML 文案一起核对数字和事实，标准列表结构序号放行；嵌套规则保留或明确拒绝。文字片段统一字体度量，标题识别最近的标题祖先，正文按最近块级或独立排版容器测行长，不合并并排卡片，并明确语义豁免、检查实际填充色；撤销也校验客户端所见版本，过期返回 409。
   - **修改放开**：模型直接改代码（换一段或整页重写）；用户用对话、预览批注点选、快捷按钮（更大胆 / 更克制 / 精简等）指定改哪里。
   - **功能部件由系统提供**：图片按编号引用、署名自动汇总到页脚；询盘表单；图标。
   - **评估四层**：① 底线检查（事实、外部资源、图片、空链接、三档溢出/重叠、对比度，不过交回模型最多两轮，仍不过如实告诉用户）；正文行长仅记录为版本检查与评估统计里的质量反馈，不触发修正轮；② 模板味检测（Impeccable 检测规则 + 反面清单，只反馈不拦截）；③ 模型看 1440/375 截图打磨一轮；④ 评估集 + 独立盲评：固定公司 × 风格一条命令生成，改 skill、提示、模型都要跑，和上一版比。
   - 后台任务显示进度、刷新可续、可停止；每次运行的步骤、检查结果、用量挂在对应版本上。预览在禁脚本沙盒里。
3. **英文版**：用户对中文站满意后再问是否生成；沿用同一结构，只翻译文字。

验收否决：事实只能来自资料或「待补充」；不得出现客户 Logo 墙、SaaS 定价、演示图、假评价/数字、空链接、未授权图片。

旧路线（区块库、adapter、白名单 operation）在新路线跑通后整套删除；旧站点一次性转成静态页面存为第一个版本。

## 素材怎么用

开源仓库、本地快照、Jiro 免费区都是可审查素材，不是成品。代码 MIT 不批准图片、字体、图标或商标。调研不等于准入，也不等于已经能生成。

## 参考站和提示词怎么用

Jiro 最大的架构课写在它自己首页上：**跨源把 Header 和 Features 硬拼，每一块会像另一个网站。** Chrome 商店还补了一句：先贴一次 Master Prompt，后面每块才共用同一套 token。对我们来说，Master Prompt ≈ 核心规范 + 所选风格，先定全站色彩和字体，再写各页。

免费整页气质不像工业，**提示词仍要看**：怎么锁一族 token、怎么写单块、怎么警告 Inconsistent Sections。学写法，不因皮不对就丢掉。Copy Prompt 不当生产提示词，也不提交进 `vendor/`。

2026-09-17 对照 [免费组件](https://jiro.build/components/free)、[免费模板](https://jiro.build/templates/free) 和工业分类后的用法：

- **学形态**：按 Header / FAQ 分区浏览 ≈ 模块选择；Collection 名是视觉族，不是行业名。
- **借结构**：克制的分栏、手风琴、三步/四步流程、询盘表。配方表见 [plan-history.md](./plan-history.md) 的「Jiro 怎么用」。接到**已准入、同一视觉族**的素材上，颜色跟当前族走。
- **工业/外贸整页**：KonsTuck、Lozitick 全是 Premium。只借「这一类站该有哪些区块」的清单。不买、不搬橙底工地皮和飞机图。
- **不用**：把免费六张整页当工业样子卡；Premium 源码；jiro MCP 进生成运行时；Copy Prompt 当生产提示词；把提示词或缩略图提交进 `vendor/`。

条款页仍 404。生成器再分发许可 unknown，所以只当内部 Demo 的配方，不能当成 MIT 素材库。
