## 0. 一页结论

- **基线是你自己的 `main`（`a1024053774/sitecraft-ai`，HEAD `5d30775`），不是 PR #4。** PR #4 只作为"能力参考库"，按能力竖切移植，不 merge、不按提交 cherry-pick。
- **实施前 main 的基线**：T1–T26 中 22 项未开始、4 项部分（T5/T9/T20/T24），只有 1 个测试文件 5 条用例，`schemaVersion` 2，8 个 AI 操作。当前已新增 CI 骨架与 T1 传输探测脚本；完整阶段 0 和产品图识别验收尚未完成，以本文“执行状态”区分已做与待做。
- **PR #4 @ `9318693`**：typecheck/build 绿，单测 797 条 794 过 1 失败（测试锚点漂移），22 套模板，93 个测试文件，63 个 e2e 文件。但有 4 类必须先修才能用的缺口（无鉴权上传、存证无 workspace 隔离、URL 搬站 SSRF、iframe `allow-same-origin`），以及把 3262 个 vendor 文件（含 1239 个 dist）全量入库的仓库卫生问题。
- **设计 Skill 不是运行时能力。** `frontend-design` / `web-design-guidelines` 只影响 Agent 工作流；DeepSeek 运行时不会读它。要让它影响生成物，必须转成项目内版本化的 `visualBrief` 契约，注入 `requestStructuredOperations` 的 `templateContext`（`lib/ai-provider.ts:82-89`），并通过 `commitOperations`。
- **shadcn/ui + Radix 在当前架构下没有生成物落点。** 16 套模板全是第三方 Astro/HTML 站点，在 sandbox iframe 里渲染，React 组件塞不进去；`components/site-renderer.tsx`（自有 React 渲染器）是死代码。因此调研稿"第二阶段 shadcn 竖切"改为 **"设计 token 竖切"**（`set_theme` + CSS 变量注入 top5 模板），shadcn 只作为 P2"原生模板轨"的候选，放在决策门后面。
- **合规底线**：进入用户生成物的第三方资产只允许 MIT/Apache 明确可再分发的来源；Tailwind Plus、Magic UI Pro、Aceternity（免费组件无独立许可证）、任何 Pro 源码一律不进生成物；21st.dev 只走官方 CLI/MCP 按需拉取并带回链，禁止镜像。
