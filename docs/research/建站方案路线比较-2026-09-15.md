# AI 建站路线比较（2026-09-15）

> 来源：只读仓库审计与方案比较。该文档是 grilling 的研究证据，不是已确认的产品规格。

## 结论

推荐 **D：混合路线**，执行内核是 **B：先把现有模板约束闭环做实，再决定是否开原生 React 模板轨**。

- A（只做 Skill + prompt + 现有模板增强）解决不了“改了看不见”、产品图无落点和模板能力不可知的问题；
- C（现在直接上原生 React/Tailwind/shadcn）在当前 iframe Astro/HTML 架构中没有生成物落点，会形成双样式栈，并错过 P0 闭环；
- B 直接解决当前用户可感知的问题；
- D 给 B 增加一个有证据才打开原生轨的决策门，防止“以后再做”变成无条件扩张。

## 仓库现实

- HEAD 为 `5d30775`，origin 为 `a1024053774/sitecraft-ai`，upstream 为 `redmaplewww/sitecraft-ai`。
- 主应用为 Next.js 16.3.1 / React 19.2.0，无 Tailwind/shadcn；主应用使用 CSS 变量。
- 16 套模板主要是 Astro/HTML，预览通过 `OpenSourceTemplateFrame` iframe，`sandbox="allow-scripts allow-forms"`。
- `SiteRenderer` 没有页面引用。
- 当前模板注入仍依靠启发式 DOM 选择器；本地 snapshot 优先，否则 fetch `demoUrl`。
- 草稿为 schemaVersion 2，商品只有 `imageColor`，没有 `theme`、`brief`、`image`。
- main 的 AI 白名单仍为 8 个操作，草稿修改统一经过 `commitOperations`。
- 当前工作树存在 T2/T3/T4 相关未提交变更，不能当作已验收能力。
- T1 已有 `content[] + image_url` data URL 的真实 HTTP 200 证据，但 JPEG、远程 URL 和服务端大小上限仍未验证。

## 四条路线

### A：Skill + prompt + 现有模板增强

**价值**：改动小，可能快速改善文案语气和初始风格。

**依赖**：vendor `frontend-design` 与 `web-design-guidelines`；继续使用现有 8 操作和启发式 bridge。

**首个切片**：把 Skill 摘要加入 `templateContext`，对 `forge` 改一次 hero 标题。

**失败点**：Skill 没有变成运行时契约；预览仍可能 miss；提问仍可能误改；无图、无主题。

**验证**：同一指令改 `hero.title`，检查 iframe 文本是否真实变化；10 条提问必须 0 次误改。

**不适合条件**：当 P0 明确要求“改了能看见、提问不改稿、产品图上架”时，A 只能作为 B 的输入材料。

### B：visualBrief + 模板契约/slot map + operations + 质量门禁

**价值**：操作只打可渲染槽位；模板覆盖报告可以进入 prompt；主题和图片有实际落点；发布前有截图、可访问性和内容门禁。

**依赖**：T2–T5 会话和 Chat v2、T6–T7 图片、T8 top5 slot map、主题和图片 operation、eval 与浏览器截图。

**首个切片**：只做 `forge`，使用显式 `{target, selector, attr}`；改 `hero.title` 后 `missingSlots=0`；提问返回 answer 且 revision 不变。

**失败点**：模板 DOM 与草稿字段不一致；fallback 冒充精确命中；brief 只进入 prompt，不能影响预览；门禁只依赖模型自评。

**验证**：slots API 返回 `covered/missing/fallbackMatched`；任务书 §7 的对话、图片和 top5 预览条目；`npm run eval` 中提问不改稿 100%。

**不适合条件**：只有在已证明第三方 HTML 槽位无法稳定覆盖企业官网结构时，才不应继续作为唯一主路线。目前还没有该失败证据。

### C：原生 React / Tailwind / shadcn 生成轨

**价值**：长期可以拥有自有组件、精确点选、主题系统和 React 同构。

**依赖**：Tailwind v4、shadcn、Radix、`site-renderer.tsx` 重写、私有 registry、生成物样式策略和许可证治理。

**首个切片**：一个 React 着陆页读取同一份草稿，并支持桌面/手机点选 target。

**失败点**：现有 iframe Astro 页无法直接容纳 React 组件；出现双栈；90 天内无法同时完成 P0；商业或不明许可证资源有再分发风险。

**验证**：生成物不再经 Astro iframe，而是出现 React 组件树；对比 iframe 轨是否仍需长期维护。

**不适合条件**：当前 P0 仍是对话、图片、槽位和发布闭环时，不应把 C 当主线。

### D：先模板约束闭环，后原生模板

**价值**：先交付“能改、能看见、能上图、能发布”，只在测到模板天花板后开启自有 React 轨。

**依赖**：前 60–75 天执行 B；原生轨必须经过单独决策门，不能把 shadcn 塞进现有 iframe。

**首个切片**：同 B，先做 `forge` 的精确槽位闭环，不引入 Tailwind。

**失败点**：原生轨被无限推迟；或者没有证据就提前开第二轨；把当前工作树 T2/T3 变更当成已完成。

**验证**：任务书门禁 + 3 个真实企业资料包跑 top5；如果精确 slot 无法覆盖 hero/服务/产品/联系，或人工仍判定为通用卡片墙，再批准一个 React 模板。

**不适合条件**：如果 90 天目标改为直接销售 React 组件建站器，D 需要重新评估；当前目标不是这个。

## 推荐的 90 天窗口

| 时间 | 重点 | 出门禁 |
| --- | --- | --- |
| D0–14 | 确认 intent；定稿 Chat/image/slot/visualBrief 契约；验收 T2；CI 在 fork 真实红绿 | 提问不改稿契约测试；文件会话刷新可恢复；远端 CI 至少跑过一次 |
| D15–45 | P0 竖切：三态意图、上下文精简、上传和看图、forge + top5 精确 slot、工作台传回 conversationId | 新建→上图→双语上架→多轮修改→提问不改→模糊澄清→发布预览；top5 `missingSlots=0` |
| D46–75 | visualBrief 进草稿；主题 token；missingSlots prompt；dry-run 回喂；约 30 条 eval；三设备截图和 guidelines 审查 | eval ≥80%，提问误改 0；主题色可见且可撤销；每个 top5 有审查记录 |
| D76–90 | P0 稳定后再做一句话建站；其余模板允许 fallback 但不能冒充精确；执行原生轨决策门 | G1 有注入/模糊/拒绝用例；书面记录开/不开 React 轨的证据 |

## 原生 React 决策门

用 3 个真实企业资料包跑 top5：

- 如果 hero、服务、产品、联系都能精确覆盖，且人工评审不再认为是通用卡片墙，继续 B，不开原生轨；
- 如果精确覆盖无法稳定达到，或视觉评审仍持续失败，才批准一个 React 模板切片；
- 不把“我更喜欢 React”当作开轨证据。

## 合规边界

生成物只接受许可证和来源可核验、允许再分发的 MIT/Apache 资产。Tailwind Plus、Aceternity 未核验资源和 Pro 源码不进入生成链路。21st.dev 只按官方 CLI/MCP 按需获取，保留可见回链，禁止镜像、抓取和训练。
