# 会话持久化失败一致性（2026-09-16）

范围：Chat SSE 在 `commitOperations` 已成功后，`appendConversationTurn` 失败时不得把已发生的 terminal result 改写成 `error`。不把文件会话与草稿伪装成原子事务。

## 复现

`globalThis.fetch` 在模型调用期间删除该 site 的 conversation 文件：conversation 已创建 → 本地 draft commit 成功 → append 得到 `Conversation not found`。

## 红 / 绿

红（修复前）：

```bash
node --test --experimental-strip-types --test-name-pattern "keeps applied result when append fails" tests/chat-route-conversation.test.ts
```

退出码 1。`done.status` 实际为 `error`，期望 `applied`。草稿 revision 与 hero 标题当时已经改掉。

绿（修复后）：同一命令退出码 0；`status` 仍为 `applied`，`conversationPersisted: false`，`conversationError` 为 `会话写入失败：Conversation not found`。answer 同路径不被改写成 error。

全量门禁：`npm run typecheck` 0；`npm test` 47/47；`npm run build` 0。

## 契约

- 保留 `applied` / `no_change` / `conflict` / `answer` / `clarify`。
- 仅在没有可保留结果时使用 `error`（provider / operation 已失败）。
- 成功路径不新增 `conversationPersisted: true`。
- 工作台按原 status 展示；`conversationPersisted === false` 另发 warning，不使用「本次没有修改草稿」。

未覆盖：真实 DeepSeek、PostgreSQL append 失败、浏览器里手工删文件。
