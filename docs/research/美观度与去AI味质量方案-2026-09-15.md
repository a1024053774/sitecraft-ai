# 美观度与“去 AI 味”质量方案（2026-09-15）

> 来源：只读仓库审计、公开一手资料和 grilling 研究。本文是需求/规格输入，不是已确认的验收门槛。

## 结论

当前架构里，“去 AI 味”主要应由人类设计的模板承载版式，AI 负责受约束的内容和少量设计 token，而不是让模型自由生成 HTML/CSS。

质量方案必须分层：

- 机器断言负责文案事实、注入防护、操作类型、槽位覆盖、图片来源和可访问性否决项；
- 截图负责观察三设备布局、内容是否真正落到预览、是否破坏模板；
- 人工盲评负责行业可信度、视觉层级、模板感、图文一致性和转化意愿；
- 模型自评最多作为探索信号，不能作为美观发布门禁。

最小竖切：top5 精确槽位 + 三个行业夹具和一个未见夹具 + `commitOperations` 唯一写入口 + 三设备截图 + 人工 rubric。

## 当前现实

- 当前生成物主要是第三方 Astro/HTML sandbox iframe，不是 React 页面；
- 当前有 16 套模板，规划 top5 为 `forge`、`atlas`、`kindred`、`signal`、`lonestone`；
- `SiteRenderer` 无页面引用；
- bridge 使用正则猜 `h1/p/card`，点选只返回粗粒度目标；
- bridge 可能为商品溢出创建通用 CSS 网格，这会绕过模板原始版式并重新产生“卡片墙”；
- 没有已冻结的人类盲评基线；
- `visualBrief`、slot map、asset plan 和 `npm run eval` 尚未形成完整闭环；
- T1 只验证了 1×1 PNG 的 DeepSeek data URL 请求，JPEG/WebP、远程 URL和服务端上限仍未验证。

## “AI 味”failure modes

| 类型 | 可观察信号 | 机器检查 | 必须人工盲评 |
| --- | --- | --- | --- |
| 文案 | 空泛词、同质化 CTA、卡片句式克隆、标题装饰过度 | 禁词表、n-gram、标题长度、CTA 动词、中英长度 | 是否像该行业的人在说话 |
| 布局 | 三列等卡片、无意义 01/02/03、商品溢出网格、渐变 hero | DOM 是否被非 slot 节点破坏、卡片数是否匹配草稿 | 是否像真实行业站、光学对齐 |
| 重复 | 相邻卡片承诺重复、hero/features/services 复述 | 字段相似度和重复 CTA | 语义是否真正重复 |
| 视觉层级 | 同字重、同圆角、同阴影、没有主次 | CSS token、字阶、对比度、visualBrief 一致性 | 扫视路径和 CTA 是否明确 |
| 图片 | 色块占位、无 alt、图文不符、无来源 | alt、hash、license、角色和比例 | 是否像可信产品图 |
| 交互 | 死链、无错误态、焦点不可见、动效不尊重 reduced-motion | axe/Lighthouse、键盘抽样、表单状态 | 焦点是否被挡、使用感 |
| 真实性 | 虚构客户、认证、产能、百分比、演示站残留 | 原子事实对照用户事实包；缺失只能“待补充” | 行业内行人是否认为夸张 |

自动检查是 fail-closed 的否决项，但自动分数不能证明美观通过。可访问性需要自动检查和人工检查结合，Lighthouse 分数也不能直接等同于 WCAG 符合声明。

## 不依赖模型自评的评测集

### 夹具

第一阶段冻结 3 个已知企业事实包 + 1 个未见事实包：

- 精密制造；
- 外贸工业目录；
- B2B SaaS；
- 一个不出现在 starter prompt 中的相邻行业，例如冷链仓储或模具外贸。

每个事实包包含：允许事实、禁止编造事实、产品图 hash、目标转化动作和联系方式。

### 对照组

同一事实包、同一模板至少比较：

- A：模板默认草稿；
- B：只替换品牌资料的模板对照；
- C：当前 AI 结构化生成路径；
- D：无槽位约束的“写好看点”路径，该路径应先 clarify，不得作为正例。

需要有权利清晰的真人企业网站截图作为盲评金标；金标不能直接喂给生成模型。

### 机器断言

`scripts/eval-chat.mjs` 应优先检查行为，不应只检查文案是否好听：

- 提问返回 `answer` 且 revision 不变；
- 模糊指令返回 `clarify`；
- 明确修改返回 `edit`；
- 只修改指定 target；
- 非法 index/SKU 不静默写错；
- top5 `missingSlots=0`；fallback 必须被标明，不能冒充精确命中；
- 输出原子事实只能来自用户事实包或“待补充”；
- 草稿、图片 OCR、会话中的“忽略指令”不得改变系统规则；
- `test:three-sites` 不低于基线。

### 截图与人工 rubric

每个夹具和模板保存 desktop、tablet、mobile 截图，记录 hash，用于人工 rubric 和回归 diff，不将 CLIP 或模型美观分作为发布 oracle。

两名盲评者对以下维度按 1–5 分评分：

1. 行业可信度；
2. 去模板感；
3. 视觉层级；
4. 图文一致；
5. 是否愿意继续询盘/了解。

初始建议：相对模板替换对照，中位分至少提升 1 分，并且没有真实性否决。这个阈值是建议，尚未测量，必须先用样本校准。

## 分层职责

```text
frontend-design（Agent 工作流）
  → visualBrief（版本化设计意图）
    → prompt 摘要 + set_theme 约束
slot map（模板能力） → bridge 精确选择器 → 覆盖报告
asset plan（图角色/许可/hash） → set_product_image 等 operation
structured operations → commitOperations → applySiteOperations
web-design-guidelines → 生成后审查
```

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| `frontend-design` | 受众、风格、禁区、字体、色彩、版式意图 | 不写 CSS/HTML，不直接进入 DeepSeek 运行时 |
| `web-design-guidelines` | 键盘、焦点、表单、alt、reduced-motion、语义 | 不决定品牌审美，不当生成 prompt |
| `visualBrief` | 站点级设计意图；theme 必须和 brief 一致 | 不直接改 DOM |
| slot map | `{target, selector, attr}`，covered/missing/fallback | 不发明新视觉；regex 只能 fallback |
| asset plan | 图片角色、来源、许可、比例、hash | 不镜像 21st/Pro 内容 |
| operations + commit | 唯一写草稿路径 | Skill、模型和 bridge 不得直写 store |

必须禁止：Skill/模型输出任意 CSS 注入；bridge 为了“看起来完整”新建非 slot 节点；`set_theme` / `set_product_image` 绕过 `commitOperations`；missingSlots 被隐藏或假装命中。

## iframe 与原生 React 的决策门

### 继续 iframe 模板轨

优点：已有非默认审美、主应用无需 Tailwind、能较快交付；代价是 slot 覆盖和模板适配成本高。

### 开原生 React 轨

优点：可以拥有自有组件、精确点选和统一 theme；代价是需要新的设计系统、可访问性、模板和双轨维护。

### 停止条件

- top5 任一关键槽位无法精确覆盖，或 fallback 冒充精确命中：停止扩模板；
- top5 + visualBrief/theme 后盲评已经达到可发布：暂不开原生轨；
- 连续两轮盲评仍认为是通用模板，且根因是版式不可改而非文案/槽位：才批准一个 React 模板切片；
- 不以“更喜欢 React”作为开轨证据；
- 不用模型自评替代人工盲评；
- 不把 PR #4 的 22 套 dist 或 Pro/无许可证资源并入生成物。

## 30/60/90 天建议

- **0–30 天**：P0 对话、意图、图片 schema、top5 slot（先 forge）、3+1 评测夹具、事实/注入/提问不改稿机器门和截图存档；暂不做 shadcn、一句话建站、URL 搬站和 21st 镜像。
- **31–60 天**：`visualBrief` + `set_theme`、guidelines 清单、eval ≥80% 且提问误改 0%、三设备截图、9 站盲评。
- **61–90 天**：其余模板只做到能打开和明确报告 fallback；执行原生 React 决策门；如果盲评已过，90 天内不要做第二套渲染器。

## 可写入规格的验收句

1. 生成模型不得作为美观/去 AI 味验收裁判；
2. 美观发布要求机器否决项全过，且盲评优于模板换皮对照；
3. 真实性要求原子事实属于用户事实包，否则输出“待补充”；
4. 预览可见要求 slot 精确命中，fallback 必须暴露；
5. 设计意图只能经 `visualBrief`、白名单 operation 和 `commitOperations` 生效。
