结论：

- **可当结构参考的是 HyperUI 和 Meraki UI**：MIT、仓库里就有完整区块源码、没有自带 JS 依赖（Meraki 的 Alpine 只在少数交互块）。借的是排法和 DOM 层级，我们在 SiteCraft 区块库里用自己的类名和 `--sc-*` token 重写；如果改写后仍保留了较完整的原结构，按 MIT 在区块库里留一份对应的版权和许可声明。
- **图片一律不用**：几个库的演示图都是外链 Unsplash、Freepik 或各自域名上的图，和代码许可无关，也不符合 T-010 的 CC0/公有领域/CC-BY/CC-BY-SA 要求。
- **图标要单独核**：Heroicons、Coolicons、Flowbite Icons、HyperUI 内联 SVG 的来源本次都没有逐个核。区块库第一版可以不用图标，或只用已核过许可的一套。
- **Preline 先不用**：Fair Use 条款里的「竞争产品」和署名要求要负责人判断 SiteCraft 这类生成器算不算，判断之前不借。
- **Flowbite 的开源仓库里没有区块**：能借的只有基础组件的结构；官网 Blocks 的条款这次没读，不作候选。

## 3. 模型写 CSS 怎么校验

### 3.1 项目现状

- `package.json` 里没有直接的 CSS 解析依赖。`node_modules` 里有 `postcss@8.5.23`，只是 `next@16.3.1` 的传递依赖；`next/dist/compiled/` 里还有 `postcss-value-parser`、`postcss-safe-parser` 等打包副本，都不是公开 API，不能直接引用。
- 没有 css-tree、lightningcss、jsdom、playwright、puppeteer。
- `scripts/check-published.mjs` 已经用 `node:child_process` 起 Chrome、用原生 `WebSocket` 走 CDP（`Emulation.setDeviceMetricsOverride`、`Runtime.evaluate`），不依赖 Playwright。三档宽度检查可以沿用这个做法，不必新加浏览器依赖。
- 工作台预览和发布页都用 `components/open-source-template-frame.tsx` 的 iframe，`sandbox="allow-scripts allow-forms"`。所以模型 CSS 漏到工作台界面不是主要风险；**真正的风险在站点文档内部**：盖住 overlay 的导航和页脚、藏掉「待补充」和缺口位、用 CSS 生成文字、拉外部资源、把版面撑破。

### 3.2 探针发现

用 postcss 解析一组有风险的样本（选择器、声明都能拿到）：

| 样本 | postcss 结果 | 含义 |
| --- | --- | --- |
| `[data-sc-block="hero"]::before{content:"全国第一"}` | 正常解析 | 必须禁 `content` 和伪元素 |
| `background:u\72 l(https://…)` | 原样保留转义，值里看不到 `url(` 字样 | **用正则黑名单查 `url(` 会漏**；值里出现反斜杠就拒绝 |
| `background-image:image-set("a.png" 1x)` | 正常解析 | 外部资源不只 `url()`，还有 `image-set()`、`image()`、`element()`、`paint()` 等 |
| `@import`、`@font-face{src:url(…)}` | 正常解析 | at-rule 用白名单，不用黑名单 |
| `body{display:none}`、`position:fixed` | 正常解析 | 选择器必须改写到区块作用域；定位和显隐属性要限值 |
| 缺右括号 | 抛 `Unclosed block` | 解析失败直接拒绝，不用 `postcss-safe-parser` 去「修」 |

另在 Chromium 141 里截图确认：**`list-style-type:"全国第一 "` 不用 `content` 也能在页面上显示文字**。所以「加不进文字」不能只靠禁 `content`，要禁掉值里的所有字符串（`quotes`、`font-feature-settings`、`grid-template-areas` 等也收字符串）。

性能：postcss 解析 6 万字符的样式 20 次共约 95 ms，解析不是瓶颈。

### 3.3 白名单怎么定

原则：**解析 → 校验 → 从结构重新序列化**。不把模型的原文透传进页面；存进草稿和 operation 的是校验后的结构，撤销也按结构恢复。

**选择器**

- 只允许以区块开头：`[data-sc-block="<区块 ID>"]`，后面最多接两级 overlay 声明过的部件 `[data-sc-part="<部件名>"]` 或标签（`h1`–`h4`、`p`、`a`、`ul`、`li`、`table`、`th`、`td`）。区块 ID 和部件名来自区块库的数据，不在清单里就拒绝。
- 伪类只放 `:hover`、`:focus-visible`、`:first-child`、`:last-child`、`:nth-child(an+b)`。伪元素全部不放（`::before`、`::after`、`::marker`、`::first-letter`、`::selection`）。
- 不允许 `*`、`html`、`body`、`:root`、ID 选择器、`:has()` 里跨出区块。

**at-rule**

- 只允许 `@media`，条件只能是项目定的断点（例如 `(min-width: 768px)`、`(min-width: 1440px)`、`(max-width: 767px)`）。
- `@import`、`@font-face`、`@namespace`、`@keyframes`、`@property`、`@counter-style`、`@page`、`@charset`、`@supports`、`@container`、`@layer`、`@scope` 一律拒绝（`@layer`、`@scope` 由服务端自己加）。

**属性（按组放行，值再各自限定）**

- 布局：`display`（`block`、`flex`、`grid`、`inline-block`、`inline-flex`，不含 `none`/`contents`）、`flex-*`、`grid-template-columns`（只收 `repeat()`/`minmax()`/长度/`fr`）、`grid-column`、`gap`、`align-*`、`justify-*`、`order`。
- 盒子：`padding*`、`margin*`（非负）、`max-width`、`min-height`、`aspect-ratio`、`border*`、`border-radius`、`box-shadow`。
- 文字：`font-size`（下限 12px，`clamp()` 的最小值也要 ≥12px）、`font-weight`、`font-style`、`line-height`、`letter-spacing`、`text-align`、`text-transform`、`font-family`（只收 `var(--sc-font-*)`）。
- 颜色：`color`、`background-color`、`border-color`、`background`（只收颜色和由 token 组成的 `linear-gradient()`），值只能是 `var(--sc-*)`、`color-mix()` 或十六进制色。

**值（逐 token 检查）**

- 放行：数字加单位（`px`、`rem`、`em`、`%`、`fr`、`deg`、`vw` 限于 `clamp()` 中间项）、`var(--sc-*)`、`calc()`、`clamp()`、`min()`、`max()`、`minmax()`、`repeat()`、`color-mix()`、`linear-gradient()`、各属性自己的关键字。
- 拒绝：任何字符串、反斜杠、非 ASCII 字符、`url()`、`image-set()`、`image()`、`element()`、`paint()`、`attr()`、`env()`、`expression()`、`behavior`、`-moz-binding`、`!important`、注释。

**必须禁掉的属性**（即使值看起来无害）：`content`、`position`（只放 `static`、`relative`，不放 `fixed`/`sticky`/`absolute`）、`z-index`、`visibility`、`opacity`、`clip-path`、`mask*`、`filter`、`backdrop-filter`、`transform`、`overflow*`（会藏住溢出，让浏览器检查失效）、`pointer-events`、`cursor`、`quotes`、`counter-*`、`list-style*`、`animation*`、`transition*`（动效 T-048 没定）、`width`/`height`（用 `max-width`/`min-height` 代替，少撑破版面）。

**大小上限**（建议值，实现时再按区块数量调）：序列化后 ≤ 8 KB；≤ 40 条规则、≤ 200 条声明；每个选择器最多三段；`@media` 块 ≤ 3 个。上限是为了审查和撤销时能看清差异，不是为了性能。

### 3.4 作用域

| 做法 | 做法说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 前缀改写 | 服务端把每个选择器改写成 `[data-sc-site] [data-sc-block="x"] …` | 所有浏览器都支持；和上面的选择器白名单是同一件事 | 只能限定上界，挡不住规则命中区块里 overlay 注入的缺口文字 |
| `@scope` | `@scope ([data-sc-block="x"]) to ([data-sc-gap])`，下界排除缺口位 | 能同时限上下界 | caniuse-lite 1.0.30001809：Chrome 118、iOS Safari 17.4、Firefox 146 起才支持，旧浏览器整段规则失效（样式丢失，不是泄漏） |
| iframe 隔离 | 预览和发布页已经是 sandbox iframe | 挡住对工作台的影响 | 不解决站点文档内部的问题，不能代替前两项 |

推荐：前缀改写为主，外面再包一层服务端加的 `@layer site-style`，让 overlay 的基础层（缺口位、导航、页脚的必要样式）放在更后面的层里优先生效；`@scope` 的下界等目标浏览器确定后再加。

### 3.5 无头浏览器三档检查

探针（Chromium 141，原始 CDP，合成一张有页头、首屏、5 张参数卡、常见问题、页脚的页面，约 96 个文字框）：

| 情况 | 375 | 768 | 1440 | 被什么查出来 |
| --- | --- | --- | --- | --- |
| 基线 | 无问题 | 无问题 | 无问题 | — |
| `.card{min-width:520px}` | 溢出 161px | 溢出 156px | 溢出 118px | `scrollWidth - clientWidth` 和元素右边界 |
| `.hero p{margin-top:-2.2em}` | 1 处重叠 | 1 处重叠 | 1 处重叠 | 文字框两两相交（H1 / P） |
| `h1{white-space:nowrap;font-size:64px}` | 溢出 281px | 无 | 无 | 只有 `scrollWidth` 查到，元素右边界查不到（元素盒没变宽，是文字溢出） |

检查项：

1. 横向溢出：`documentElement.scrollWidth > clientWidth`，外加列出超出视口的元素，给用户说明用。两种都要，缺一种就会漏（见上表第 4 行）。
2. 文字重叠：`TreeWalker` 取所有非空文字节点，`Range.getClientRects()` 取框，不同父元素的框相交超过 2px 算重叠。几百个框两两比较耗时可以忽略。
3. 文字被藏：对比加 CSS 前后草稿里每个槽位文字是否仍然可见（有尺寸、在视口宽度内），避免被缩成 0 或挤出去。
4. 只拒绝**新增**的问题：先不带模型 CSS 跑一次基线，带上再跑一次，只看差集，避免 overlay 自己已有的问题把每次修改都拦下。

耗时：Chrome 冷启动约 0.86 s；已启动后，一个页面三档检查约 0.19–0.23 s（这张合成页没有图片和网络字体）。真实页面要等图片和字体加载，估计 1–3 s；应常驻一个 Chrome 进程复用，不要每次 operation 冷启动。基线结果可以按「草稿修订号 + overlay 版本」缓存。

局限：只查三档宽度、首屏以下要滚动整页才能查全（这次用视口高 900、整页排版，`getClientRects` 返回整页坐标，不受视口高度限制）；颜色对比度和最小字号可以在同一次 `Runtime.evaluate` 里顺带查，这次没测。

### 3.6 三个做法

| | A 结构化样式 operation | B CSS 文本 + postcss 白名单 | C CSS 文本 + css-tree 语法校验 |
| --- | --- | --- | --- |
| 模型输出 | JSON：`{block, part?, media?, declarations: {属性: 值}}` | 一段 CSS 文本 | 一段 CSS 文本 |
| 解析 | 不用 CSS 解析器；zod（已有依赖）校验结构，值用一个小 tokenizer 或 `postcss-value-parser` | `postcss`（MIT，8.5.28，约 218 KB）+ `postcss-value-parser`（MIT，4.2.0），都要加成直接依赖 | `css-tree`（MIT，3.2.1，约 1.36 MB），用它的 lexer 按 CSS 语法校验值 |
| 安全面 | 最小：选择器由服务端从 block/part 拼出，模型碰不到选择器语法 | 中：选择器要逐段校验再改写 | 中：语法合法不等于安全，白名单一样要写 |
| 和 T-048 原话 | 模型不是在「写 CSS 文本」，但表达力和 B 相同（B 的白名单本来就只放区块和部件选择器） | 贴合 | 贴合 |
| 成本 | 最低 | 中，两个新依赖 | 高，依赖大，白名单工作量不减 |

**推荐 B，存储用 A 的形状**：模型照 T-048 写 CSS 文本；服务端用 postcss 解析，逐条对照 3.3 的白名单，转成 A 那样的结构化规则存进 operation；页面上用的 CSS 由服务端从结构重新生成（加前缀和 `@layer`），不透传模型原文；再跑 3.5 的三档检查，不过就拒绝并把溢出或重叠的位置告诉用户。如果负责人不想加依赖，退到 A：让模型直接输出结构化规则，校验和浏览器检查不变。C 不推荐。

## 4. 需要负责人或 T-048 定的事

- 加 `postcss`、`postcss-value-parser` 两个直接依赖（推荐 B 时），还是走 A 不加依赖。

- 三档检查要在运行时起 Chrome。开发机没问题；部署环境本阶段不做，实现时只需记下这条前提。
