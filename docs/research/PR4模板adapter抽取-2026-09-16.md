# PR4 模板 adapter 抽取与 Docker 记录（2026-09-16）

状态：声明槽位、快照加载/就绪提示已通过本轮代码与浏览器验收；两套 Next 静态导出、SPA 预渲染和客户素材替换/准入仍未完成。提交收据见主任务回报与 `docs/project/plan.md`。
依据：用户确认不整仓搬 PR4；模板用 submodule；不要把正则命中当成精确槽位；模型负责意图。

## 1. 结论

1. **意图用模型，落点用声明槽位，不用正则冒充精确命中。**
2. PR4 的 adapter 精华是「每模板一份可审查映射 + 共享预览引擎」，不是 5700 行 JS 字符串，也不是 1612 行 `template-preview-bridge.ts`。
3. 多出的 6 套模板已按 submodule 挂进本仓库，只钉源码 SHA，不提交 dist。
4. Docker 核心栈（postgres / redis / mailpit / web）已有本地镜像。`pull_policy: missing` 允许已有镜像直接启动；MinIO 目前不被应用使用，已置于可选 profile。此前镜像拉取失败是环境观测，本文不将其外推为发布历史或停发结论。

## 2. 槽位方案评估：模型 / 声明选择器 / 正则

要拆成两件不同的事，不能用一个机制同时做。

| 问题 | 该谁做 | 不该谁做 |
|---|---|---|
| 用户这句话是改稿、回答还是追问？改哪些字段？ | 模型意图（现有 `edit` / `answer` / `clarify`） | 正则扫 DOM |
| `hero.title` 写到页面哪个节点？ | 模板声明的 slot map（选择器 / `data-slot`） | 每轮让模型猜 DOM |
| 没声明的板块怎么办？ | 报告 `missing`，必要时生成区或请用户确认 | 用标题文案正则 silently 写入 |

**推荐组合：模型意图 + 声明槽位。**

- 模型已经在做「想干什么」。再让它每轮识别 DOM，会不稳定、费 token，并且违反「非法 target 不静默错改」。
- 声明槽位是版本化数据，可测、可报 covered/missing，和 `commitOperations` 对齐。
- 默认不采用正则写稿；只有经过明确授权和验证的例外才可记录为 `fallbackMatched`，不能写成精确命中。初始 bridge 的 `/about|feature|service/` 猜写已在本轮移除，固定 HTML 清理规则不作为槽位命中。

PR4 后半段自己也收敛到同一结论：集合槽位（features/services items）拒绝猜；猜错比不写入更糟。

不采纳的方案：

- **运行时用模型找节点**：无冻结证据，刷新/换模板会漂。
- **整文件搬 PR4 adapter**：`prepareFn` / `nativeFillFn` 是字符串源码，和 22 套模板绑定，正是臃肿来源。
- **只用正则继续撑 22 套**：能出预览，但不能当验收。

## 4. Docker

本机已有（2026-09-16 重建后实测）：

- `sitecraft-ai-web:latest`（`b6b72f9c77e4`，约 1.16GB，含 adapter 构建结果与 22 套 vendor 源码）
- `postgres:16-alpine`（`cf78e76683b9`）
- `redis:7-alpine`（`ff02b58f971e`）
- `axllent/mailpit:latest`（`98b916bd3c8d`）
- 构建基座 `node:22-alpine` 已在 Docker 构建缓存中（本次 rebuild 未再从 Hub 拉失败）

`docker-compose.yml` 各服务已设 `pull_policy: missing`：镜像在本地就直接装载，不访问 Hub。完全断网可用：

```bash
docker compose --env-file .env.local up -d --pull never
```

已实测（2026-09-16）：`GET /api/health` 返回 `persistence.driver=postgres` 且 `database=ready`；库中有 `sitecraft_sites`、`sitecraft_conversations`。

限制：

- MinIO 为未被当前应用使用的可选服务，默认不启动；镜像的实际可获取性需独立验证。
- 本地镜像不会自动跟上游安全更新；要更新须显式 `pull` / 重建。
- web 镜像是构建时快照；以后改代码要再 `build web`，不是改文件即热更新。
- `up --pull never` 只保证**已有镜像**脱网启动。本机当前没有名为 `node:22-alpine` 的标签（构建层在 cache 里）。若 cache 被清，下一次 `build` 仍可能要拉 Node 基座；这和「启动已有 web/postgres」不是同一件事。
- 容器内预览若缺本地模板快照，仍可能 fetch 上游 `demoUrl`（这是应用网络，不是 Docker 拉镜像）。

- 只执行声明且唯一匹配的槽位；移除分区/卡片猜写和自动商品网格。空字符串可以清除旧文本；不支持的结构操作保持在 missing 中。
- forge 的 hero、真实页脚联系方式和三张手写服务映射可落地；screwfast 的 hero/CTA 与四张优势映射可落地。screwfast、tailwind-landing 首页不存在的 contact 字段明确 missing，不制造联系区。
- 模板列表动态统计 22 个候选；当前机器 5 个本地静态预览。无快照的详情页没有编辑 CTA，所有素材仍标待核验。
- 当前工作树 typecheck/test/build 全绿（45 tests，包含尚未提交的聊天测试）；模板定向 23 tests。最终独立只读验收：`57638423-a32d-43ae-922b-a4197c2f8f72`，PASS；不等于全站发布合格。

剩余项没有标完成：

1. **Next 两套静态导出**：nextjs-landing 与 shadcn-landing2 的 pinned config 未启用 `output: 'export'`。需要受控修改源配置或新的构建方案；本轮未改 submodule 源码，不用 `.next` 伪装快照。
2. **SPA 预渲染**：shadcn-landing 的锁文件与 package 不一致，普通 Vite 构建仍是空壳；不能只改状态为可生成。
3. **客户素材准入**：许可核验已完成研究记录，但素材替换/删除、notice 与发布端阻断尚未实现；仍不能把这些演示素材作为客户事实或已授权客户产物。
4. **直接 URL/发布路径**：gallery/detail 只做能力展示门禁；手动 `/workspace?template=...` 和原发布路径尚未统一服务端生成/发布准入，不把 UI CTA 隐藏当安全边界。
5. **页面/导航业务**：本轮只验收声明内容与报告；脚本移除后的完整菜单、表单、多页交互另需符合业务契约的实现与验收。
6. **更多集合槽位**：只在手写映射且真实模板存在时接入，不恢复正则猜写。
7. **独立提交/推送**：仅把本渲染子模块、六个 gitlink 和证据提交到 fork；聊天、CI/T1、无关暂存内容保留。
