## 一、按项目优先级排的结论

### 1. 画板批注（负责人点名最重要；对应「更好改」）

komo（`@tjcages/komo` v0.7.0，MIT，版权方 Lué Studio）值得借的是交互骨架，不是锚点方式：

- **可借**：透明捕获层、悬停描边、点选和拖框、批注位置按目标元素的相对比例记录、页面变化后重新测量、找不到目标时明确标为「脱离」而不是猜。
- **不能照搬**：komo 的锚点是通用 CSS 选择器加文字匹配，找不到时按 `nth-of-type` 拼路径。这违反我们「未命中报 missing，不按顺序或文字猜写」的硬约束。我们的预览已经有 `data-sitecraft-slot` 和 T-069 的稳定产品/卡片 id，地址比 komo 稳。
- **位置**：预览 iframe 带 `sandbox="allow-scripts allow-forms"`，工作台读不到 iframe 里的元素，所以点选和圈画必须由 `lib/template-adapters/preview-bridge.ts` 完成，再把结构化结果发给工作台。
- **缺口**：撤销现在只能撤最后一步（`lib/site-store.ts`，历史最多 50 条），「撤掉某条批注带来的修改、保留后来的修改」需要新增目标级的冲突检查。
- **建议的第一步**：最薄的端到端试做——点一张产品卡 → 写一句批注 → 模型只改这个产品 → 能单独撤销，后来又改过同一处时提示冲突。批注存在站点外的独立文件，不进草稿。

### 2. 生成页质量（对应「更好看」）

**色彩（R2）**
- 不建议把 103 套色卡做成用户选项。现有 6 套色彩集（青花瓷、石墨工坊、工程暖橙、铜锈、松石、莫兰迪）已覆盖 B2B 主要方向。
- 真正的缺口是色阶：每套只有 10 个扁平角色色，自定义品牌色用 HSL 简单压暗。建议新增一个 OKLCH 色阶模块，从一套种子色展开中性色、主色、语义色，并逐项检查 WCAG 对比度。S007、S021、C16 三套试展开后，四个样子的正文和按钮对比度都达标（仅离线计算，未在浏览器截图验证）。
- RAL 名称、色号、Logo 需要授权，产品里只能出现自有命名的 HEX 值。

**字体（R5）**
- 四个样子里只有工程工业写了中文字体，另外三个完全依赖系统回退，中英混排的字宽和高度不可控。补齐中文回退栈是零风险的小修。
- 推荐的开源字体（均为 OFL）：工程工业 Geist + Geist Mono；样本目录 Manrope + JetBrains Mono；明快 Sora + Manrope；灰底短路径 Geist。发布页不能用 Google Fonts 外链，只能自托管；中文字体子集化的体积还没实测。
- Fontshare 的 Satoshi、Clash Display、Ranade、Cabinet Grotesk、Chillax 是 ITF FFL 2.0 许可，不可用于生成器：条款明确禁止把字体做成第三方用户生成自己内容时可选的字体。推荐组合里没有用到它们。

**区块与动效（R3）**
- 生成站区块结构参考：Arc UI 免费仓库（MIT）、Space UI 的数据表、时间线、筛选形态。都依赖 React，只能手工改写进区块库，走 T-073 流水线。
- 生成站动效候选：Transitions.dev（纯 CSS，带 reduced-motion，许可允许随产品交付）。第一批只评估 FAQ / 型号详情展开、产品行悬停描边、表单提交成功提示。MAP 里「生成站动效」还没有规格，需要先开决定票。
- 不建议：Reverse UI、Planes、Skecher UI、Kobra（许可未清或付费，粒子、发光、3D 风格重）。

**规则与自动检查（R4）**
- 20 条军规里有 5 条我们完全没覆盖（先灰度后上色、组间距 > 组内间距、基线对齐、强调色边框、慎用边框），其余多数只有原则、没有判定。
- 最值得做成自动检查的 5 条：正文对比度 4.5:1（现在只有 3:1）、正文行长 45–75 字、声明组的基线对齐、组间距 > 组内间距、每页只有一个主按钮且文案是具体动作。
- oil-ui 的「认品类 → 定调性 → 先定骨架 → 截图对比 → 独立审查 → 做减法」可以补进 T-073 的候选说明；它允许模型自由写 HTML/CSS，这一点和我们的硬约束冲突，不照搬。
- 小程序设计只迁移「每页先确定主要任务」，用于页面规划（T-002）和需求对齐提问。

**图标（R5）**
- 生成站暂不全站加图标，T-051 结论继续成立。值得做一次局部试验：联系方式和认证状态行，文字版与图标版交给盲评对比。
- 真要加，复用工作台已有的 Lucide（ISC），内联 SVG，模型只选图标 id。Amicons、Smallbits 的许可不允许生成器式再分发，未取得书面授权前不能用。
- Cursor 图标文章可用来定图标规范：网格、尺寸档、描边粗细、一概念一图标的概念表。

### 3. 工作台（自用产品 UI）

## 三、需要负责人决定的问题

每题第一项是推荐。

1. **批注现在开工吗？** T-064 写的是「等评分之后写批注规格」，评分已由 T-071 停止。
   - 推荐：现在开批注决定票，并按 R1 的推荐答案定下面 7 个子问题。
   - 或者：先做第 2–4 项页面质量的票，批注排在后面。
2. **批注的 7 个子问题**（R1 第 8 节，推荐项依次为）：批注单独存文件、不并入站点记录；只认稳定 slot，不留通用选择器兜底；圈中多个目标时记录全部目标，由用户指定主目标后才允许模型修改；「当时看到什么」默认存文字快照，截图由用户主动选择；先用轮询，不建实时通道；撤销冲突按目标逐个检查；批注由用户确认后才关闭。
3. **发布页正文对比度 4.5:1 是否升为硬门？** 推荐：升为硬门，图片背景测不了的报「未测」。
4. **图标试验做不做？** 推荐：只做联系方式和认证两个区块，盲评不通过就删掉。
5. **字体走自托管还是只用系统字体？** 推荐：英文自托管 OFL 字体，中文先用系统字体，等子集体积实测后再定是否自托管中文。
6. **要不要联系 Minor Adventures 询问 Amicons / Smallbits 的生成器授权？** 这是对外联系，只能由负责人决定或亲自做。推荐：暂不联系，先用 Lucide。
