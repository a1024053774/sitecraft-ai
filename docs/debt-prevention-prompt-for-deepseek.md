# 技术债防复发 · 执行提示词（DeepSeek 用）

> 用法：整段复制。三阶段逐次放行，每阶段做完停下等确认。
> 本次只加规则与门禁，业务代码零改动——验收由千问独立复审。

---

## 角色与总目标

你是我的项目的债务治理工程师。前四轮契约治理已完成（成果见 `docs/glossary.md` 与 `docs/plans/2026-09-12-*.md`）。本轮使命：**让已付过学费的债不再长回来**——把这轮所有教训变成每个后续 agent（你、Codex、其他）写代码时必须路过的规则，和跑不过就合不进去的机器门禁。

## 背景事实（据此判断轻重，不要当成客套话）

1. 本项目代码大量由 AI agent 产出。**agent 不主动读文档，只认被注入的文件和跑红的测试**——教训不写进 AGENTS.md、不变成测试，等于没沉淀。
2. 本轮真实发生过的债形态，每一条都付过代价：
   - 平行手写契约（prompt 手抄枚举/容量，与 schema 脱节）→ 线上越界整批失败；
   - "测试绿但门从没生效"的假门禁 → 防线裸奔了不知多久；
   - 注入字符串里的反引号提前终止模板字面量 → 踩了六次；
   - sed 批量改名撞变量名、tsc 未必报 → 靠肉眼发现；
   - 幂等键两处手拼且已漂移（一个用 item.id 一个用 index）→ 无测试能变红，只有真实冲突时静默丢操作；
   - 同值不同源：24/12/80/240/2000/1000 多处手抄。

## 阶段 A · 军规成文（AGENTS.md）

先通读 `docs/glossary.md`（核心术语 + 三条附则）与 `docs/plans/2026-09-12-phase4-rename-and-compat-design.md`，然后在 `AGENTS.md` 追加一节「契约军规」。要求：**不超过 20 行，每条要么有机器门禁背书、要么有明确的肉眼检查动作**。必须覆盖：

1. 新增字段名/枚举值/容量与长度数字：禁止字面量，必须从权威来源派生（`site-document.ts` 的 zod schema、`SLOT_MAX_LENGTH`、`sectionKeys`、`LEGACY_OPERATION_NAMES`）。找不到派生路径就停下提问，不许手抄。
2. 任何新增检查必须"证明会失败"：先注入坏样本拍红、再修复拍绿（附则 3），负向验证输出贴在 commit 里。不许以"测试本来能过"为由跳过。
3. 注入用字符串（prompt / 页面脚本的模板字面量）内禁用反引号。
4. 批量文本替换（sed/正则/脚本改代码）：改前列出撞名与匹配范围，改后做行为不变性比对。tsc 全绿不算通过证据。
5. 巨型文件（点名清单：`app/api/templates/[templateId]/preview/route.ts`、`app/workspace/page.tsx`、`app/generate/page.tsx`）拒收新代码：先拆出所属子模块，再写新功能。
6. 新增操作名/协议字符串：与别名表 + append-only 快照测试同 commit 登记，不许事后补。
7. 发现来不及修的问题：在 glossary 待办区登记 T-x 并写明处置意向，禁止口头挂账。

产出军规原文，停下等确认；确认后进阶段 B。

## 阶段 B · 机器门禁（按此优先级逐项做）

1. **pre-commit 钩子**：提交时跑 `npx tsc --noEmit` 与 `npm test`。用原生 git hooks（`core.hooksPath` 指向仓库内目录），**不引入 husky 等新依赖**。负向验证：造一个必挂类型的临时文件试 commit，贴拦截输出，再删除。
2. **手抄检测测试**（新增 `tests/prompt-handcopy-guard.test.ts`）：扫描 prompt 构造代码（`lib/site-intent.ts`、`lib/site-generator.ts`、`lib/ai-provider.ts`、`lib/template-catalog.ts`）中手写的枚举值清单——竖线拼接的操作名/板块名、中文释义 Record 字面量、未 import 常量的字符数数值——命中即红。设显式迁移白名单文件，**只允许列出既有 T-3/T-4 项，禁止新增白名单条目**。负向验证：故意回插一处 `"features|services"` 手写串 → 红；删除 → 绿。
3. **同值不同源检测**：对已点名数值（24、12、80、240、2000、1000）做扫描，两处出现且无 import 关系即红。若现状误报过多，把规则收窄到点名清单并说明取舍，**不许为了绿而放宽成永真**。
4. **门禁盘点自检**：`scripts/gate-inventory.mjs`，登记本轮全部门禁（反引号、契约回归、别名快照、手抄、同值），支持 `--prove`：逐类注入坏样本证明各自会红。跑一次，全清单先红后绿输出附进收口报告。

每项一个 commit，commit message 附负向验证原文。任何门禁拿不准误报范围时停下报告，不许先放宽阈值混过去。

## 阶段 C · 流程成制

1. `AGENTS.md` 增加「提交前强制自检」小节，与阶段 B 门禁一一对应——人或 AI 提交前都要过。
2. `package.json` 加一个 `prove-gates` script（调 gate-inventory --prove），并在 glossary 附则登记"每季度或新增门禁后必须跑一次"。
3. glossary 附则追加一行收口记录：日期、本轮新增门禁清单。

## 硬性红线（违反 = 回滚重做）

- **业务代码零改动**：全部 diff 只允许出现在 AGENTS.md、docs、tests、scripts、package.json、hooks 目录。收口报告里 `git diff --stat` 自证。
- 禁止修改或放宽任何既有测试来让新门禁变绿；有冲突就收窄门禁作用域并报告。
- 不引入新依赖；hooks 用原生 git 能力。
- 任何门禁若无法证明会红，不合入，报告"证明不了的原因"。
- 三阶段结束各停一次等放行；阶段内不许跳序。

## 验收标准（我方独立复核）

- 军规 ≤20 行，逐条能对应到一个门禁或一个明确检查动作。
- 手抄检测与同值检测各有"故意回插坏样本→红、清除→绿"的原文证据。
- pre-commit 在人工制造失败时真实拦下 commit（有输出为证）。
- `prove-gates` 全清单先红后绿。
- `npm test` 只增不减（基线 695，2026-09-12 实测 694 pass / 1 skip，以执行当日实际数为基线）、tsc 0 错误、业务代码 diff 为零。
