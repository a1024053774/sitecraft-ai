## 新增能力（评估完成）

### T20. 🆕 **从截图提取图片**（评估通过，可做）
| 项 | 内容 |
|---|---|
| **解决什么** | 一直以来的最大缺陷：**"抠不出截图里的照片"** → 工厂站的产品图/背景图只能占位 |
| **实测方案（已验证）** | ① 让模型给出图片的**坐标框** ② 按**缩放系数**换算到原图坐标 ③ 用 `sharp` 裁剪 |
| **实测结果** | **成功抠出沙丘照片**（65KB 有效图像，不再是空白） |
| **关键坑（必须记住）** | 模型给的是**它自己缩放空间**的坐标，不是原图像素。实测原图 1440 宽、模型按 **800 宽**给坐标 → **缩放系数 1.8**。直接按原图裁会裁出**空白**（实测 3.5KB vs 65KB） |
| **依赖** | ✅ `sharp` **项目已装**（实测可用） |
| **局限（如实）** | **只在单张图上验证过**。多图、重叠遮挡、半透明背景等复杂情况**未验证** → 实施时要做容错 |
| **成本** | 定位坐标 **1.5 秒 / 57 tokens**，可忽略 |
| **出处** | §七 风险 3 |
| **状态** | ⬜ **评估通过，待实施** |

### T19. 🔴 修 SVG 存储型 XSS（**现在就存在**）
| 项 | 内容 |
|---|---|
| **现状** | 上传白名单**接受 `image/svg+xml`**（`lib/product-image-store.ts:22`）；读取接口原样回 `Content-Type: image/svg+xml`，**无 CSP、无 `X-Content-Type-Options`、无 `Content-Disposition`** |
| **危害** | SVG 可内嵌 `<script>`。同源提供 = **存储型 XSS**：用户上传恶意 SVG → 他人打开 → **脚本在我们的域名下执行** |
| **为什么现在修** | **本设计会让上传接口接受更多素材（截图），攻击面只会更大** |
| **修法（成本极低）** | 读取接口加 `Content-Disposition: attachment` 或 `Content-Security-Policy: default-src 'none'` |
| **用户已确认** | ✅ 一起修 |
| **出处** | §4.10.3 |
| **状态** | ⬜ |

## 验收口径（设计文档 §六）

| # | 标准 |

| 1 | 上传风机截图 → 产出一个模板，**全程无人工干预** |

| 8 | **输入把关生效**：传非网页截图 → **生成前拦下** + 人话说明 |
