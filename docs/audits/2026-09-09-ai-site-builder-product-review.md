# AI 建站功能：产品经理视角的痛点与无用功评审

**日期**：2026-09-09
**方法**：走真实用户旅程读代码取证（`[read]`），每条结论附文件行号；测试基线 `npm test` 437 项全绿。
**视角**：产品经理——判断「用户能不能走完核心旅程」「哪些功能建了但走不到」。

---

## 一、一句话结论

**AI 建站的核心旅程在前半段（理解需求 → 匹配模板 → 生成文案 → 预览）是通的，后半段（填入真实素材 → 交付站点 → 持续运营）大面积断裂。产品把「内容」窄化成了「文字」，而企业官网的内容主体是图片、资质和产品；同时有多个页面是「演示态」——看起来能用，实际不接真实数据。**

---

## 二、核心旅程实测：断点在哪

| 步骤 | 用户期望 | 实际 | 判定 |
|---|---|---|---|
| 1 一句话需求 | 输入需求 | 通（意图理解 + 追问/拒答） | ✅ |
| 2 匹配模板 | 看到推荐 | 通（22 模板 + 评分） | ✅ |
| 3 生成文案 | 等初稿 | 通（批次生成 + 进度 + 补全） | ✅ |
| 4 预览 | 看到成品 | 通 | ✅ |
| **5 填入真实内容** | **上传厂房/产品/资质图** | **文字可改，图片基本不能换** | ❌ **断** |
| **6 交付站点** | **导出/发布** | **导出页无入口；发布靠 iframe 加载** | ⚠️ **半断** |
| **7 持续运营** | **看询盘、改内容** | **线索页通；内容页是假数据** | ⚠️ **半断** |

## 三、P0 痛点（阻断核心价值）

### 3.1 图片资产无法替换 —— 「demo 感」的真正根因

**证据**：`lib/template-asset-registry.ts` 登记 22 个模板首屏主视觉的**可替换性**，实测：

| 情形 | 模板数 | 证据 |
|---|---|---|
| 可替换 | 12 | `selector:` 12 条 |
| 首屏无 `<img>` | 5 | powerai / awesome / astropaper / nextjs-landing / shadcn-landing2（`unsupportedReason: "no_img_element"`） |
| 主视觉是 CSS 背景图 | 2 | astrogent / devportfolio（`css_background`） |
| 主视觉是内联 SVG | 1 | signal（`svg_only`） |
| 首屏最大图是 logo | 2 | shadcn-landing / astrofy（`logo_only`） |

**更严重的是产品图**：`draft.products[].image` 字段存在，但**没有任何上传入口**——
`app/workspace/page.tsx` 的资产弹窗只处理 `hero.image` / `brand.logo` 两类目标。
用户想让产品有图，只能靠 CSV 里填外部 URL。

**产品后果**：工厂官网的说服力 80% 来自实拍图（厂房/设备/产线/资质）。用户改完文字、点开预览，看到的仍是模板的示例图——**这就是反复被反馈的「很 demo」**，根因不是 AI 写得差。

### 3.2 首页是演示态 —— 建完站回首页找不到自己的站

**证据**：`app/page.tsx:21-46` 的 `sites` 是**硬编码数组**（Forge Industrial / Morrow Advisory 等 3 个假站点）；
`grep fetch|api/sites app/page.tsx` **零命中**——该页不读任何接口。
`:154` 的链接是 `href={site.name === "Forge Industrial" ? "/workspace" : "/workspace"}`（三元两边相同）。
统计数字 `03/24/18` 与「↑ 比上月多 18%」为常量。

**产品后果**：用户的核心动作是「建站」，但**首页不显示他建的站**。这是信任级别的缺陷——
比功能缺失更伤，因为用户会怀疑「我刚才做的那个站去哪了」。

### 3.3 设置页与「团队协作」全是死按钮

**证据**：`app/settings/page.tsx` 全文 `grep -c onClick` = **0**；页面文案却承诺「管理品牌、通知、成员和发布默认值」。
侧边栏 `components/app-sidebar.tsx:40` 的「团队协作」指向 `/settings#team`——即同一个死页。
`app/settings/page.tsx:49` 还写「仅开放 Owner 角色」，与代码里的 `editor/reviewer/viewer` 三角色模型矛盾。

**产品后果**：产品承诺了一个协作能力，实际零实现。

## 四、P1 痛点（价值受损）

### 4.1 「内容与商品」页展示的是示例数据

**证据**：`app/content/page.tsx:35` 的 KPI 与卡片列表都渲染 `starterProducts`（`lib/site-model.ts` 里的写死示例商品），
而非当前站点的真实商品。

**产品后果**：一个叫「内容与商品」的页面，用户以为在管理自己的商品，实际看到的是别人的示例。

### 4.2 导出能力存在但无入口

**证据**：`components/real-template-export-button.tsx`（「下载真实模板」）**只在** `app/export/[siteId]/page.tsx:56` 使用；
而 `grep '/export/' app/ components/` **零命中**——**没有任何页面链接到导出页**。

**产品后果**：用户拿不到「可交付给客户的文件」。对一个「AI 建站」产品，导出/部署是交付闭环的最后一环。

### 4.3 询盘表单：20/22 模板无可用表单

**证据**：`scripts/scan-lead-forms.mjs`（静态）与 `scripts/probe-lead-form.mjs`（渲染）双探针一致——
22 个模板仅 astrogent、shadcn-landing2 自带 `name`/`email`/`message` 齐全的表单。

**产品后果**：发布出去的站，访客无处提交询盘 → 「线索」功能对多数模板是空的。

### 4.4 设计 token 覆盖模板原生样式

**证据**：`lib/site-generator.ts:61` 每次生成无条件写 `set_design_tokens`；
`app/api/templates/[templateId]/preview/route.ts:355-357` 注入
`body{font-family!important}` / `button,[class*=card]{border-radius!important}` / `main>section{padding!important}`。

**产品后果**：卖点说「真模板不是换肤」，实际 22/22 模板的字体/圆角/间距被替换——**卖点自相矛盾**。

## 六、设计层面的根因

| 根因 | 表现 | 影响面 |
|---|---|---|
| **「内容」被窄化为「文字」** | 只有 `hero.image`/`brand.logo` 两个资产槽；产品图无入口；资质/厂房/团队图无槽位 | 核心价值循环断在「填真实内容」 |
| **演示态与真实态混用** | 首页、内容页、设置页三处用写死数据；导出页无入口 | 用户无法判断「哪些是真的」 |
| **投入结构与价值分布错配** | 大量精力在模板适配与生成质量；素材与交付几乎为零 | 模板和生成是及格线，素材才是差异化 |
| **同一缺陷三次显形** | 「真模板」被 designTokens 覆盖、「可编辑」缺图片、「询盘闭环」缺表单 | 三个卖点各有一个说不出口的例外 |

## 七、优化建议（按价值/成本排序）

| 优先级 | 建议 | 为什么 | 验收标准 |
|---|---|---|---|
| **P0** | 素材提升为一等公民：产品图上传 + 内容图片槽位（厂房/设备/资质/团队） | 这是 demo 与真站的分水岭 | 用户能为每个产品上传图；至少 3 类内容图可替换 |
| **P0** | 图片替换覆盖 22/22：CSS `background-image`、内联 SVG 形态也要支持 | 10 个模板的用户当前完全无法换首屏图 | 探针报告「可替换 22/22」 |
| **P0** | 首页接真实数据：列出当前工作区站点 | 建完站找不到自己的站是信任级缺陷 | 建站后首页出现该站 |
| **P1** | 导出入口接进工作台；发布改为静态化输出 | 交付闭环的最后一环 | 工作台一键下载单文件站点 |
| **P1** | 内容页接真实商品；设置页死按钮要么实现要么删 | 演示态比缺失更伤信任 | 内容页显示当前站点商品 |
| **P1** | 询盘表单按三层方案重做（模板原生优先） | 20/22 模板当前收不到询盘 | 探针 22/22 |
| **P2** | 资质证书区（ISO/专利/认证） | 国内工厂站刚需，也是 P4 前置 | 新节通过门禁 |

---

## 八、下一步

1. **先修 3 个 P0**——它们都指向同一件事：让用户能把「自己的东西」放进去、看到、拿得到。
2. **清理 10 项无用功**——其中 3 项是产品债（不可达功能/假入口），优先处理。
3. **重估投入方向**——素材与交付的投入应从 0 提到与模板适配同量级。
