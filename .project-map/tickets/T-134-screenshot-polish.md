## Why

T-127 批准的流程是「读资料 → 大纲 → 写页面 → 检查修正 → 看截图打磨 → 存版本」，截图打磨这一步还没做。T-132 证明只改规范文字没有可测改善（`artifacts/blind-t132-2026-10-08/`，混排 8/8，跨轮选新版 3/8）。评审认出生成页的依据大多在截图上一眼可见：页头与首屏重复同一按钮；首屏参数在后文再列、导语与正文同义复述；首屏统一「左大标题 + 右四格参数」骨架；超大标题孤字折行（「件」「计」单独一行）；全站同一种细线等宽条目节奏。

## What to build

整站生成通过底线检查后，系统按真实预览为每页截 1440 与 375（复用 T-133 修好的采集链路，预览照旧禁脚本），把截图和当前站点代码交给 deepseek-flash 看图（复用 `lib/preview-vision` 的调用方式）。看图提示给出上面这类可见问题作为自查方向（引导口吻，不是规则清单），并让模型先说出它在截图里看到的具体问题，再给出改后的完整站点代码。改后的代码照常经唯一提交入口（清理 → 底线检查 → 存版）；底线不过按现有最多两轮修正处理，仍不过就保留打磨前的版本并如实记录打磨失败，不静默放过。打磨一轮，不循环。打磨前后各是一个版本，版本摘要写明「截图打磨」和模型看到的问题，用户可以在版本历史里恢复。对话修改不自动打磨（本票只做首次生成）。

## Acceptance

- [ ] 真实入口端到端：一站生成后自动打磨，版本历史里有打磨前、打磨后两个版本，摘要列出模型看到的问题；打磨后底线检查结果写进版本
- [ ] 失败路径：打磨后候选底线不过两轮时保留打磨前版本并如实显示，有测试且坏实现（静默存版或丢弃打磨前版本）失败
- [ ] 用 `npm run eval:new-route -- --previous <T-133 基线轮>` 在机器空闲时跑一整轮，交主控安排三种口径独立盲评；Resolution 写拒收率、用量与基线对照
- [ ] Astra 审查通过；typecheck、test、build 通过
