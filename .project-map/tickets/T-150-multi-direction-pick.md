## Why

T-146：用户在一个抽象的风格名和两个滑杆之间做选择，很难预料结果。Oil UI 的做法是先把几个真正不同的方向并排摆出来让人挑。T-149 证明「出发点」有效之后再做；无效就关掉本票。

## What to build

需求对齐确认之后、生成整站之前，加一个可选步骤：模型按 T-149 的方法给出 2–3 个方向，每个方向只写首页首屏（同一份资料、同一提交入口，存成候选，不算正式版本）。任意两个方向在版式、字体、配色、首屏视觉这四项里最多只能有一项相同。工作台并排显示首屏缩略图（真实渲染截图，1440 和 375），用户挑一个后（可附一句意见）再生成整站，没被选的候选按 T-003 保留，不自动删除。选项走结构化请求保存，刷新后能恢复（和需求对齐同一机制）。默认是否开启、一次出几个，按 DeepSeek 预算在 Resolution 里给出建议，由主控决定。

## Acceptance

- [ ] 浏览器测试走真实入口：出方向 → 刷新恢复 → 挑选 → 生成整站 → 撤销；1440/768/375 截图看过
- [ ] 方向差异由独立盲评判定：同一公司的 2–3 个方向不应被认为是同一模板；挑中方向生成的整站与不挑直接生成的整站做成对比较（T-143 口径）
- [ ] 每次挑选增加的 token 写进 Resolution
- [ ] Astra 审查通过；typecheck、test、build 通过；spec、intent、CONTEXT 同步
