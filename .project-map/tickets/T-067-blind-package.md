## What to build

把 T-065 的 6 个基线站和 T-066 的 3 个专家站打成一个盲评包，交给没参与过的评分者（T-068）。

- 包目录 `artifacts/t067/blind/`，评分者只看这个目录。对照表 `artifacts/t067/blind-key.json` 放在包目录**外面**。
- 每个页面一个随机 4 位十六进制代号（9 个页面 9 个代号，不按组共用），文件名 `<公司>-<代号>-<zh|en>-<宽度>[-masked].png`，公司用 c1 / c2 / c3，顺序随机，不能从文件名、元数据、图片内容看出哪个是专家版、哪个是第几次生成（检查截图里没有 siteId、调试标记）。截图直接用 T-065 / T-066 渲染脚本的输出，重新起名即可；需要重渲就重渲，并看过。
- 每家公司一份资料摘要 `materials-c<n>.md`：从 `lib/simulated-packs.ts` 原样摘公司事实、产品和参数、缺失事实清单（去掉「模拟」核验说明以外不要删内容），用来让评分者核对有没有编造事实。
- 每家公司 3 个采购任务，写在 README 里，答案必须能在资料里找到：例如「找到型号 X 的某参数」「区分两款产品的主要差别」「找到询盘入口」「指出一项资料里没有、页面应显示待补充或不显示的信息」。任务和答案在对照表里另存一份，README 只放题目。
- 成对比较清单：每家公司把三个页面两两配对（3 对），每对按 AB、BA 两种顺序各出现一次，全部打乱顺序编号，共 18 题。
- README 原样写入下面的「评分说明」。

## 评分说明（写进 README）

第一部分：逐页绝对评分。每个代号单独评，先不要和别的页面比。每项 1–5 分，按描述打分：

1. 行业匹配。1 = 看不出行业，像 SaaS 或通用落地页；3 = 看得出行业，但像通用模板换了词；5 = 版式、信息、用词都像这个行业里认真做的厂家官网。
2. 信息层级与选型。1 = 找不到关键信息，或参数被截断、重叠；3 = 信息都在，但要费劲找，或者有重复、疏密失衡；5 = 采购在半分钟内能找到型号、关键参数和询盘入口。
3. 视觉完成度。1 = 明显破版、重叠、截断；3 = 没有错误，但平淡，像线框或半成品；5 = 像专业设计师交付的成品，三档宽度都成立。
4. 公司特异性（看遮字版）。1 = 换任何公司名都成立；3 = 内容是这家的，版式是通用的；5 = 版式、视觉重心、区块安排都体现这家公司的业务重点。只因为产品数量不同而看起来不同，不算特异。
5. 可信度。1 = 明显是模板或假的；3 = 能看，但有空话、元话术（描述资料或建站过程的话）或可疑的说法；5 = 像一家真实公司自己的官网。
6. 总体：像不像这家公司自己建的官网，1–5 分。
7. 合格判断（是 / 否）：能不能直接拿给这家公司的老板看，不需要先道歉。是 = 总体 ≥ 4、没有一项 ≤ 2、没有硬伤。

硬伤单独列，每条写图名和位置：页面上有资料里没有的事实（对照 `materials-c<n>.md`）、不属于这家公司的品牌或 Logo、客户 Logo 墙、定价、演示图、假评价或编造的数字、空链接、占位文字、元话术；中英文页内容对不上；任一宽度破版、重叠、截断、横向溢出。

采购任务：按 README 题目，只看截图作答，写出答案和在哪张图的哪个位置找到；找不到就写找不到。

第二部分：成对比较。全部绝对评分写完以后再做。按题号逐题回答：哪个更像这家公司自己建的官网（A / B / 持平），一句理由，指到具体区块和宽度。
