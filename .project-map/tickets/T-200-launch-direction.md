## Question

T-199 关闭后 frontier 清空。下一批做什么？

## Resolution

负责人 2026-10-20 的决定：

1. **停止质量开发，准备上线**。原话：「不做了，把东西收拾收拾上线吧」。AGENTS「本阶段不做」里的公网部署，这次按负责人的明确要求执行。
2. **产品页**：做一个简约艺术风的产品页，可以跳转到建站网站；从已生成的好站里挑几版做样品展示。由执行主控亲自做，不派 Codex。先出初版给负责人看，上线后再按反馈调整。
3. **用户自带模型接口**：建站网站提供入口，让用户自己填 API 地址和 key。
   - 配置只存在用户浏览器的 storage 里，不存服务器。
   - 建站资源也存在用户本地，包括站点、版本、对话和上传。
   - 先不做注册登录。
4. **GitHub**：README 等页面更新，加上产品页和建站网站的入口。
5. **部署**：VPS 约 1 核 1GB，使用 luckye.online 的子域名。
6. **清理**：清掉缓存与各工作树。

构思主控的实施假设（负责人可以更正）：

- **key 的处理**：用户的 key 只在每次请求时经 HTTPS 发给服务器，服务器只在这次处理的内存里使用，不写盘、不记日志、不进任务记录。生成、检查流程仍在服务器上跑，因为需要无头 Chrome。
- **生成结果**：服务器处理完把结果交回浏览器保存，处理中的数据只在内存里短暂停留。
- **兼容范围**：只保证 DeepSeek 兼容接口可用，因为系统依赖严格函数调用和思考模式。
- **内存**：1GB 内存要加交换内存，生成并发限为 1。

实施拆成 T-201 到 T-204。
