## Question

T-110 盲评 NO_GO 后，T-123 两轮审美评审仍未过。根因：模型只能从白名单挑 operation、往固定区块填字，排版由开发侧写死，每家公司都是同一副骨架。是否放开、放开到什么程度？

## Resolution

2026-10-07 负责人决定直接换路线（不先做小试验），并确认 Claude 的方案「可行，就按这个来」：

1. **模型直接写站点代码**（每页 HTML + 公共页头页脚 + 一份 CSS），取代 T-048 的区块库拼页。流程固定、内容放开：读资料 → 页面大纲 → 写页面 → 检查修正 → 截图打磨 → 存版本。
2. **Skill 两层**：核心规范每次加载（taste-skill MIT、Impeccable craft floor Apache-2.0、本项目去 AI 味 skill、盲评反面清单提炼）；风格由用户选：主风格单选 + 版式/密度两个滑杆 + 默认「帮我选」，风格卡用本系统真实生成的缩略图。oil-ui 的「多方向挑选」、Hairline 等距线稿示意图、反推优秀官网提示词放在后续批次。
3. **Harness**：Notion 式版本库（每次修改一个完整版本，撤销/恢复也是新版本，左列表右预览）；唯一提交入口（清理 → 底线检查 → 存版本）；修改放开（对话、预览批注、快捷按钮都由模型直接改代码）；功能部件由系统提供（图片编号与署名、询盘表单、图标）；评估四层（底线检查 → 模板味检测 → 截图打磨 → 评估集 + 独立盲评）；后台任务可续可停、运行记录挂在版本上；预览沙盒。
4. **硬规则只留**：事实只来自资料或「待补充」；无脚本、外部资源、未授权图片；所有修改走同一提交入口、可恢复；删除只由用户决定。
5. **英文版**不和中文一起生成：用户对中文站满意后再问是否生成英文版，沿用同一结构只翻译文字（取代 T-009 的「中英文一起生成」）。
6. 新路线跑通后旧的区块库、adapter、白名单 operation 整套删除，不留兼容层；旧站点一次性转成静态页面存为第一个版本。T-123、T-124、T-126 作废，T-123 分支不合并。

依据：2026-10-07 实测，deepseek-flash 配核心规范初稿和两种风格各写一版首页（`artifacts/route-probe-2026-10-07/`），两版差别明显、照片挨着对应产品、无脚本外链、数字都来自资料；单页 100–140 秒、3–4 万 token。Claude 自查，不是盲评。

规则落在 `AGENTS.md`「生成路径的硬约束」、`docs/project/mainline.md`、`docs/project/intent.md`、`CONTEXT.md`。第一批票：T-128、T-129、T-130。
