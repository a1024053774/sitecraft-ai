## Question

T-204 公网验收发现：在这台 1 核 1GB VPS 上，局部修改的动态状态检查一定超时；整站生成也会让 CPU 满载数分钟。这会挤占负责人在同一台机器上的其他业务。可选做法：换 2 核 2GB 机器、只在这台放宽检查时限，或者接受限制。

## Resolution

负责人 2026-10-21 的决定，原话：「满载可能会影响我的其他业务，这个先搁置吧，这个 sitecraftapp 的，然后里面也可以放上我这个网站的一些交互式页面来展示，就是我可以直接在产品页上点击我的这个工作台的按钮来看看这套流程，用预设好的，这个交互式界面尽可能的展示我们网站的功能，最后你在我本地部署好，我刚刚安装了 docker，你就按 Docker 多阶段镜像加 docker-compose 编排 PostgreSQL 这套来」。

1. **公网不再运行真实建站**。VPS 上的建站服务搁置，以免满载影响负责人的其他业务。检查时限和检查规则都不改。
2. **改为交互式演示**。sitecraftapp.luckye.online 放一套交互式页面，用预设数据，尽可能展示建站网站的功能。产品页上的「工作台」按钮进入这套演示。演示不调用模型，也不在服务器上跑检查（T-207）。
3. **真实建站部署在负责人本机**。用 Docker 多阶段镜像，加 docker-compose 编排 PostgreSQL（T-208）。这一项本属 AGENTS「本阶段不做」里的「完整 Docker 镜像重建」，此次按负责人明确要求执行一次。

构思主控的实施假设（负责人可以更正）：

- **VPS 上的建站服务只停用不删除**：安装目录、AppArmor 配置和 install.sh 都保留，以后换机器时可以直接复用。
- **演示用真实生成结果**：演示里的站点和版本取自已有的真实生成结果（例如 342ed662 与产品页样品），并明确标注「演示，预设数据」，不冒充实时生成。
- **T-204 带已知问题关票**：生成、刷新恢复、站点包、服务器扫描均已通过；局部修改与撤销在 1 核机器上无法通过，记录在 Resolution 中。局部修改与撤销改在 T-208 的本机部署上验收。
