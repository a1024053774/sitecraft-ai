## Question

负责人原话：「丰富生成网站的样式，盲评分不出是模版拼的，现在还是很单薄，并且很多模版都不能用。」约束：内部 Demo，不碰部署。不在范围：公网部署、实机测试、真实客户试点。

现状（2026-10-04）：区块库 14 种区块、每种 1–5 个布局（沿革、质检流程只有一种）；生成站没有照片，只有 CSS 示意（T-015：真实工业官网首页靠实拍）；4 个生产样子已迁进区块库，`vendor/` 里 23 个开源模板快照未移植；侧边栏「AI 建站」进的是模板画廊 `/templates`。

## Resolution

2026-10-04 负责人拷问后确认（D 编号对应拷问记录）：

- **验收口径（D2、D10）**：两种盲评都要过，只做二选一盲猜、不打分（T-071）。
  - 混排盲猜：每轮 3 家公司，每家放生成页 + 2 张真实工业企业官网截图，审查者猜中生成页的比例 ≤ 50%（随机为 33%）。真实官网截图由 agent 从公开站点采集，只用于内部审查，不进仓库。
  - 同样子换公司：同一个样子换两家公司，审查者判「同一模板」的比例 ≤ 50%。
- **单薄的来源（D3、D11）**：没有图片、排法少、静态细节质感不足。这一批不加新样子，只用现有 4 个。
- **图片（D7、D13、D14）**：两条腿。
  - 测试用真实图：Codex 为工业、外贸、注塑三份模拟资料各找 6–10 张许可清楚的照片（CC0 / 公有领域 / CC-BY / CC-BY-SA，内容要和这家公司的行业对得上，T-010），覆盖产品、设备、厂区 / 车间、检测；每张记录来源和许可；通过工作台已有的图片上传接口（`/api/sites/[siteId]/images`）进草稿，不直接改草稿文件。
  - 示意图：只用在需要图而资料里没图的位置（首屏、设备、产品配图位等），由 Codex 按样子的 token 画线稿式 SVG，**风格要符合当前页面**，能看出是示意、不冒充实拍；和 T-093 图标一样过盲评，不过就删。
- **开源模板（D4、D8）**：`vendor/` 里的模板只拆成区块候选，补进现有 4 个样子的区块池（走 T-073 的 AI 味审查流水线），优先补只有一种排法的区块；不整套移植成新样子。
- **展示与入口（D9、D12）**：下线模板画廊 `/templates` 和单个模板预览页；侧边栏「AI 建站」直接进工作台新建站点，用户在需求对齐卡里选样子和色彩集作为预设。效果展示等系统做全面后再做，展示的是系统真实生成的页面。`vendor/` 快照留在仓库只当拆区块的素材，不再展示给用户。
- **细节质感（D5、D6）**：只做静态细节（排版层级、数字 / 参数排法、分隔线与表面处理、卡片细节）；动效不放进这一批。
- **顺序（D15）**：① 下线模板画廊、入口改到工作台；② 测试图片 + 图片区块打通；③ 开源模板拆区块，先补单一排法的区块；④ 示意图 + 静态细节质感；⑤ 按上面的口径跑两种盲评验收。

拆票由主控按这个顺序进行，每张 build 票各自写验收。
